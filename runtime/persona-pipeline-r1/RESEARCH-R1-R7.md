## R1과 R2에서 먼저 고정할 비교 기준

**평가 정본을 주입 블록과 분리한다.** 100토큰 블록에서 성격 지침이 빠졌는데 그 짧은 블록으로 채점하면 성격 의무 자체가 사라져 좋아 보일 수 있다. 모든 조건은 동일한 전체 persona 정의와 동일한 루브릭으로 비교해야 한다. 주입 블록 기준 운영 판정은 관찰 열로만 둔다. 정본의 이름뿐 아니라 실제 내용 해시·revision·judge 지침 해시가 조건 간 같아야 한다.

이 지적은 `035bf8578c`로 전달했고 풀스택이 `6917489a0f`에서 반영했다. 오케스트레이터는 `70d22bcca8`에서 `51eeb340`의 `basis:canonical`과 별도 `basis:injected` 판정을 보고했다. **이는 담당자 보고이며 클로버의 운영 검증이 아니다.** DB 현재 판을 읽는 경로라면 실행 기간 중 정본이 바뀌지 않았는지도 실행 담당자가 기록해야 한다.

계수는 세 가지로 분리한다: 컴파일러 추정 길이, 공급자 방식의 메시지 계수, 실제 캐시 포함 입력량. 내부 관문에 대한 인프라 설명상 `elda_usage.input`은 캐시 밖 입력이고 `input+cacheRead+cacheWrite=prompt_tokens`다. 블록 유무의 차분은 프레이밍을 포함한 **증분 입력 사용량**이며 독립 블록의 정확한 토큰 수로 이름 붙이지 않는다. 공식 Claude 계수 문서도 사전 계수를 추정치로 설명한다. [Token counting, 확인 2026-11-14](https://platform.claude.com/docs/en/build-with-claude/token-counting)

30개 고유 상황 × 세 반복을 90개 독립 상황으로 세지 않는다. 조건별 차이·불확실성·실패·기권을 남기며, 같은 상황과 반복·시점을 묶는 분석이 필요하다. 간판 22과제는 구조 회귀로 유용하지만 원의뢰의 축별 30개를 자동 충족하지 않는다. 40턴을 제외하면 20턴까지의 축소 범위로 사전에 명시한다. 긴 대화에서 persona 충실도 저하를 관측한 연구는 이 평가의 필요성을 뒷받침하지만 우리 모델의 실패 시작점을 알려 주지는 않는다. [Persistent Personas, EACL 2026-03](https://aclanthology.org/2026.eacl-long.246/)

**자동 판정 비용도 별도 계수한다.** 오케 보고상 강제 블록 턴은 canonical과 injected 판정을 각각 호출한다. 생성 1,440회라면 자동 판정만 추가 2,880회가 될 수 있다. 독립 A/B 평가를 따로 돌리면 그것도 더한다. 자동 canonical 판정을 A로 재사용하는 설계라면 동일 응답·고정 기준·독립 판정 정의를 충족하는지 명시하고 같은 호출을 중복 계산하지 않는다. 이 수치는 다른 실행 담당자를 위한 규모 설명이며 클로버의 집행 계획이 아니다.

## R3 네 필드 출력 계약의 근거와 통제 조건

Claude 공식 문서는 JSON schema를 따르는 constrained decoding과 strict tool use를 구분한다. native JSON 출력은 `output_config.format`이며, 구조화 출력을 쓰면 형식을 설명하는 추가 시스템 지시와 입력 토큰·캐시 영향이 생긴다. refusal·출력 상한 중단은 정상적인 형식 결과와 구분해야 한다. [Structured outputs, 확인 2026-11-14](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)

따라서 다음 두 연구를 섞지 않는 것이 좋다.

1. **의미 분할 계약 비교:** 같은 persona·정본·주제·모델·추론·출력 상한에서 plain 답과 정체/받아줌/답/다음 걸음 계약을 비교한다. 형식 지시만 정의된 차이로 둔다. 네 필드는 모델이 실제로 생성한 문장이고 렌더러는 순서대로 이어 붙이기만 한다. 한 조건에만 이름·설명·정답을 추가하면 R6까지 바뀐 비교가 된다.
2. **형식 강제 비교:** 네 필드 의미 계약을 양쪽에 동일하게 두고 지시문만 사용할 때와 공급자 schema 강제 사용을 비교한다. 형식 준수·유효 응답 도착률·의미 품질·토큰을 분리한다. 강제 tool call로 우회하면 요청/응답 형태와 호출 의미도 달라지므로 native schema와 같은 처리라고 부르지 않는다.

위 구분은 공식 기능 설명에서 도출한 연구 설계다. 특정 출력 계약이 Haiku persona 품질을 높인다는 직접 실측 근거는 아니다. 내부 관문이 현재 OpenAI `response_format`을 Anthropic 형식으로 옮기지 않는다는 인프라 보고(`7c73034657`)와 공급자 자체에 구조화 출력 기능이 있다는 공식 설명도 구분한다. 관문 기능 부재를 공급자 기능 부재로 확대하지 않는다.

## R6 정본 값 삽입은 무엇을 보장하는가

계획과 문장 실현을 나누는 data-to-text 연구는 명시적인 의미 계획과 제약이 유용할 수 있음을 보여 준다. 후속 연구에는 entity/relation 타입 힌트와 검증 단계도 포함된다. 이를 우리 파이프라인에 적용한다는 것은 **설계 추론**이며, 한국어 persona·Haiku에 대한 효과 크기는 아니다. [Step-by-Step, NAACL 2019](https://aclanthology.org/N19-1236/), [Plan-based generation, INLG 2019](https://aclanthology.org/W19-8645/)

두 조건은 같은 입력 사실·행위 계획과 같은 질문을 사용해야 한다. 한쪽이 모델에게 계획까지 새로 만들게 하고 다른 쪽만 정답 계획을 받으면 삽입 효과와 계획 효과를 분리할 수 없다. 렌더러가 바꾼 위치와 값, 바꾸기 전 출력, 최종 사용자 문장을 모두 남기는 방식이 적절하다.

| 평가 층 | 확인할 것 | 통과해도 보장하지 못하는 것 |
|---|---|---|
| 모델 출력 | 조수·사용자 슬롯을 맞게 선택했는가, 값과 근거의 주체를 이해했는가 | 사후 삽입 덕분에 맞아진 이름을 모델 정체성 성공으로 셀 수 없음 |
| 렌더러 | 정본 문자열·숫자·고유명사를 손실 없이 넣었는가 | 잘못 선택된 슬롯, 잘못된 조사 연결이나 문장 의미까지 자동 교정되는 것은 아님 |
| 제품 응답 | 누가 무엇을 했는가, 부정·시점·요청/완료·실행 가능성이 맞는가 | 이름 문자열 존재만으로 이 층의 정확성을 대체할 수 없음 |

예를 들어 정확한 조수 이름을 넣었어도 그것을 사용자의 이름이라고 설명하면 귀속은 틀린다. “연락을 할 수 없다”와 “연락을 완료했다”도 같은 이름과 장소를 포함할 수 있다. 그러므로 파이프라인 초안의 **‘사실 오류는 전부 계산 가능한 값’**이라는 일반화는 **‘일부 정본 값의 표면 오류는 결정론적으로 줄일 수 있다’**로 좁히는 편이 근거에 맞는다.

한국어 어미·받침 정규식은 관찰 열로만 둔다. 문자열 치환이나 형태소 포함 여부를 의미·정체성 gate로 사용하지 않는다. 역할·부정·행위 상태의 판정은 고정 루브릭과 원문 근거를 통해 평가해야 한다.

## 판정자와 홀드아웃에서 필요한 근거

MT-Bench/Chatbot Arena 연구는 LLM 판정의 순서·길이·자기 선호 편향과 한계를 보고한다. 여기서 얻을 수 있는 결론은 사람 표본과 편향 점검이 필요하다는 것이며, 논문 속 모델의 일치율을 현재 judge의 정확도로 복사할 수는 없다. [LLM-as-a-Judge, NeurIPS 2023](https://arxiv.org/abs/2306.05685)

같은 Sonnet을 별도 세션에서 두 번 썼다는 사실만으로 서로 독립된 오류라고 가정하지 않는다. κ와 원시 일치율·라벨 분포·기권률을 함께 남긴다. 양성/음성 반반 보정 묶음의 정밀도도 실제 위반 빈도가 다른 서비스의 운영 정밀도와 동일하지 않다. 사람 20개는 의뢰의 최소 수집량이지 작은 오류율을 입증하는 충분한 표본이라는 뜻이 아니다.

홀드아웃은 후보를 고정한 뒤 제한된 횟수로 평가하고, 결과를 보고 수정했다면 그 자료는 개발 자료로 재분류해야 한다. 적응적 평가에서 테스트 세트를 반복 참조할 때 생기는 문제는 독립된 연구 주제다. 여기서는 차등프라이버시 기반 재사용 방법을 구현하거나 그 보장을 주장하지 않으며, 별도 봉인·개봉 기록을 제안한다. [Generalization in Adaptive Data Analysis and Holdout Reuse, NeurIPS 2015](https://proceedings.neurips.cc/paper/2015/hash/bad5f33780c42f2588878a9d07405083-Abstract.html)

현재 검색에 등장하는 *Reliability without Validity* (`2606.19544`)는 원문에서 **2026-11-03 arXiv Admin 철회**를 확인했다. 해당 수치·주장을 이번 판단 근거로 채택하지 않았다. [철회 상태](https://arxiv.org/abs/2606.19544)

## 이 회신의 완료 범위

완료한 것은 외부 원문 검토, R1~R7 근거 매핑, 설계상 혼동 요인과 판단 범위 정리다. 실제 블록 곡선·장기 대화 결과·판정자 보정 수치·사람 라벨·홀드아웃 사전 등록은 실행 담당자의 후속 산출이다. 이번 의뢰의 모델 생성 호출은 0회이며, 사용자 범위 변경 뒤에는 내부 health/models 조회도 하지 않았다.

범위 변경 전 관문 읽기 관측은 [과거 관측 기록](GATEWAY-AUDIT.md)에 시각과 판을 구분해 보존했다. 이후 v1.002·R1 판정 분리 등의 변경은 담당자 Comms 보고이며 직접 검증으로 표시하지 않는다. 클로버의 관문 접근 요청은 철회됐다.
