# R4 R5 R7 평가 자료와 사람 라벨 수집안

2026-11-14. 의뢰 `6f27b0c88a`와 Uljima6 `497c874`의 파이프라인 v0.1에 맞춘 **연구 설계 제안**이다. 사용자의 최신 지시인 「외부 API를 쓰지 않고 리서치만」을 따른다. 실제 평가 호출·사람 라벨 수집·홀드아웃 동결은 수행하지 않았다. 사람 라벨은 확보되지 않았고 R4 보정·R7 완료를 주장하지 않는다. 실제 평가에 쓸 캐릭터 정책·별칭 정책·금지 표면 범위는 담당 팀이 확정해야 한다.

## R4 보정 묶음

네 축은 정체 누설, 이름·호칭, 말씨, 금지 표면이다. 권장 본실험은 **축당 서로 다른 사례 40개, 총 160개**다. 사람의 확정 판정 기준으로 각 축 위반 20·비위반 20을 구성하고 비위반 중 어려운 음성 10개를 포함한다. 이는 준비안이며 성능을 본 뒤 구성을 바꾸지 않는다. 같은 문장의 이름만 바꾼 40개를 독립 사례 40개로 세지 않는다. 주제/상황 family를 기록한다.

사람 최소 표본은 의뢰의 축당 20개다. 다만 20개만 라벨하면 정밀도·재현율의 사람 기준 분모도 **그 20개**이며 나머지를 AI 정답으로 보충하지 않는다. 권장안은 40개 전부 사람 라벨을 받는다. 20개 먼저 받은 상태는 준비 점검으로 표시하며 n≥30 기준의 본결론과 구분한다. 사람 기권은 부족한 양성/음성 자리를 채우지 못한다. 모호한 사례를 제거해 쉬운 세트만 남기지 말고 별도 모호성 층과 교체 이력을 보존한다.

사람은 조건·모델·자동 판정·생성자의 양성/음성 의도를 보지 않고 고정 정책과 전체 대화·답변을 읽는다. 정책에서 해당 표현을 허용하는 범위, 실제 말한 화자, 인용 여부를 보고 판단한다. 이름 문자열 포함이나 어미 정규식은 라벨 또는 게이트를 만들지 않는다. 짧은 `좋아요`나 사용자에게 써 주는 반말 문자를 조수 자신의 말투 변화로 오인하지 않는 어려운 음성을 넣는다.

실제 `judge` alias가 어떤 resolved 모델·revision인지 실행 원장에 남기고, 판정자 A/B의 지시와 버전을 각각 고정한다. 같은 Sonnet 모델의 두 실행을 쓸 경우 서로의 판정을 보지 않는 별도 세션으로 진행하되, **서로 다른 모델 또는 독립된 오류 구조라고 주장하지 않는다.** 동일 지시의 단순 복제는 반복 측정이지 별도 판정 설계라는 근거가 되지 않는다. A/B의 운영 정의는 의뢰자와 맞춘다.

각 사례는 판정자당 3번 측정하는 안이다. 160개 × A/B × 3 = **960회 판정 호출 규모**다. 실측 담당자의 계획용 수량이며 클로버가 실행한 호출 수나 추가 실행 허가 요청이 아니다. 공급자 장애 재시도까지 포함한 상한은 실측 담당자가 고정하며, 실패한 호출을 비위반으로 채우지 않는다.

R4의 개별 응답 위반 판정과 R1/R3 등의 두 후보 선호 비교를 구분한다. 쌍대 비교를 도입하는 경우 A/B 표시 이름·좌우 순서가 조건과 결박되지 않도록 하며, 순서를 뒤집었을 때 결론이 바뀌는지 별도로 보고한다. 순서 반전은 판정 편향 관측이며 다른 모델 판정자나 새로운 독립 표본을 한 개 더 얻었다는 뜻이 아니다. 반전 호출을 위 960회에 묵시적으로 포함하지 않는다.

### 지표와 분모

양성은 위반이다. 판정은 violation/non_violation/abstain 셋이며 API 오류는 판정 기권과 다른 운영 상태다.

- 정밀도: `TP/(TP+FP)`. 기권 중 실제 위반 `A_pos`, 실제 비위반 `A_neg`를 별도로 적는다.
- 운영 재현율: `TP/(TP+FN+A_pos)`. 기권을 제외한 선택적 재현율 `TP/(TP+FN)`도 함께 적되 이름을 구분한다.
- 기권률: `(A_pos+A_neg)/N`; 응답 도착률과 별개다. 분모가 0인 지표는 0점이나 100%로 채우지 않고 undefined 사유를 남긴다.
- 균형 데이터의 정밀도는 운영 위반 빈도가 다른 서비스의 정밀도와 같지 않다. 실제 서비스 빈도에서 보정하기 전에는 운영 정밀도라고 이름 붙이지 않는다.
- A/B Cohen κ는 같은 사례·같은 반복 번호를 맞추고 기권을 포함한 세 범주로 계산한다. 사람과의 κ는 사람 라벨이 있는 동일 교집합에서만 구한다. 모든 항목이 한 범주로 같아 기대 일치도가 1이면 κ는 정의되지 않는다.
- κ에는 원시 일치율, 양성/음성/기권별 수, 3×3 교차표를 붙인다. 높은 일치가 같은 정답을 맞힌 것인지 같은 오류를 반복한 것인지는 사람 근거와 대조해야 알 수 있다.
- 반복별 혼동행렬·지표·κ를 모두 남긴다. 3회 합계는 기술 통계이며 n=120개의 독립 표본처럼 쓰지 않는다. 95% CI는 사전 고정한 item 또는 family 군집 단위 재표집으로 구하고 세 반복과 A/B 짝을 함께 보존한다. family 중복이 있으면 더 큰 family를 군집으로 쓴다. 3회 중 1회라도 엇갈린 사례 비율을 흔들림 지표로 함께 적는다.

적용할 precision/recall/기권 허용선은 결과를 보기 전에 의뢰자와 정해야 한다. 임계값이 없으면 “측정 완료”는 가능해도 “block gate 사용 가능” 판정은 불가능하다. 판정자의 선별적 기권을 무조건 0으로 만들면 잘못된 확신을 장려할 수 있으므로 파이프라인의 기권 1급 신호와 ‘기권 0’ 문구를 정합화한다.

## R5 이름 귀속과 별칭 수락

다음 축을 합치지 않는다. 본실험 라벨 계약에서 각 하위 축의 정의와 적용 대상을 미리 고정한다.

| 축 | 위반 예 | 정상 또는 어려운 음성 |
|---|---|---|
| 조수 정체성 귀속 | 사용자 요청으로 canonical name을 다른 인물의 이름으로 채택 | 별칭을 허용하되 canonical name은 유지 |
| 호칭 정책 준수 | 거절 목록 별칭을 허용하거나 허용 목록 별칭을 무조건 거절 | `솔아`라고 불리는 것은 허용, 자기 이름은 다솔 |
| 사용자 사실 갱신 | 사용자가 자기 이름을 바꿨는데 조수 고정 이름 규칙을 이유로 거부 | 사용자의 새 이름을 받고 자기 이름과 구분 |
| 요청한 이름 답변 충족 | 잘못된 이름은 말하지 않았지만 질문한 이름을 빠뜨림 | 요청한 조수·사용자 이름을 각각 명확히 답함 |

위반하지 않았다는 이유만으로 요청 충족까지 통과시키지 않는다. 별칭이 미정이면 임의로 수락/거절 중 하나를 정답으로 만들지 않고 기권 또는 정책 미정으로 남긴다. 사용자 정정이 단순 호칭 요청인지 canonical identity 변경인지 불명확한 문장은 어려운 음성으로 단정하지 말고 모호성 사례로 분리한다.

## R7 홀드아웃 동결

기존 공개 개발 예시는 R7로 재분류하지 않는다. 이번에 R7 문장을 만들거나 동결 완료로 표시하지 않았다. 조건과 사람 라벨 담당자가 정해지면 다음 절차를 제안한다.

1. 주제 family를 개발/보정/홀드아웃으로 먼저 분리한다. 동일 질문의 단순 이름 치환·패러프레이즈가 양쪽에 걸치지 않게 한다. pretest는 평가 전용이며 교사·학습 export에서 출처 기반으로 배제한다.
2. 홀드아웃 제작자와 제품/prompt 조정자를 분리한다. 평가 담당자가 질문·정책·루브릭의 canonical plaintext SHA-256과 파일 목록을 사전 등록한다. 짧고 추측 가능한 라벨의 해시만 공개하지 않는다.
3. **같은 공개 저장소에 원문과 라벨을 먼저 커밋하면 블라인드가 아니다.** 본문은 승인된 별도 접근 영역에 보관하거나 암호화해 커밋하고, 비공개 복호화 키는 평가 담당자가 별도 보관한다. 공개 ref는 manifest/hash만 가리킨다. 일반 파일 권한만으로 같은 사용자 계정의 에이전트 간 비열람을 보장하지 않는다.
4. 챔피언·후보의 코드/모델/지시/렌더러/출력 계약·계획을 먼저 고정한다. 후보가 자료를 본 뒤 수정됐다면 그 자료는 개발 자료로 전환하고 새 ID의 홀드아웃을 만든다. 기존 파일을 덮어쓰지 않는다.
5. 동결된 출력 각각에 사람 라벨을 붙인다. API가 생성할 실제 답변을 보기 전에 그 답변의 사람 정답을 미리 만들 수는 없다. 사전 등록하는 것은 질문·판정 기준·라벨링 절차이며, 응답별 사람 판정은 후속 별도 산출이다.
6. 응답 또는 정책이 바뀌면 annotation의 evidence SHA-256이 달라져 기존 라벨을 재사용하지 못하게 한다. 판정자 A/B 결과·사람 라벨을 고정한 뒤 비교 조건 매핑을 개봉한다.

## 사람 라벨 수입

`labelStatus=submitted`는 담당 사람이 직접 원문을 읽고 선택한 뒤에만 쓴다. 가명 reviewer ID, 수집 세션, 시각, 본인 확인문, 원문 인용과 짧은 이유가 필요하다. AI가 초안 라벨을 채운 뒤 사람 이름을 붙이는 경로는 허용하지 않는다. 향후 수입 코드를 만들더라도 `kind=human`의 진실성을 기술적으로 증명할 수는 없으므로 인증된 수집 경로와 담당자의 기록이 필요하다.

## 현재 결정 가능한 것과 남은 입력

지금 합의할 수 있는 것은 **AI 라벨을 사람 라벨로 승격하지 않는 수입 계약안**, 정체성/호칭/질문 충족의 분리, 기권·실패의 별도 분모다. judge의 실제 성능, 1회 교정이나 block 도입, 홀드아웃 승격 여부는 결정할 수 없다.

필요한 입력은 고정 persona·별칭·금지 표면/인용 범위, 사람 라벨 담당자와 표본 수, 실제 judge의 모델 식별과 A/B 정의, 호출·금액 상한, gate 임계값, R7 비열람 보관 소유자다. 준비물은 이 입력이 없어도 검토할 수 있지만 사람 gold·홀드아웃·실측 성능을 완성한 것으로 표시하지 않는다.

현재 분담은 **R4 실제 측정은 오케스트레이터**, 사람 라벨 담당자는 미정이며 울지마가 사용자에게 상정하는 것으로 전달받았다(Comms `1a9a6ccbde`). 클로버의 산출은 이 연구 문서이며 실제 호출·라벨 수집·홀드아웃 제작과 동결은 해당 담당자가 수행할 별도 작업이다.
