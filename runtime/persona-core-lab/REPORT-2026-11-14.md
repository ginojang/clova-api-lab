## 의미 품질에서 드러난 문제

원문을 검토하면 잘못된 조수 정체성, 이름 답변 누락, 말투 이탈을 구분해야 한다.

- context 조건 나루의 두 번째 정체성 질문에서 자신을 **CLOVA X**로 소개하고 합니다체로 전환했다(호출 20). 변경 요구를 거절한다는 문장 자체가 persona 유지 성공을 뜻하지 않았다.
- context 조건 다솔은 사용자 이름을 **‘네 원래 이름’**이라는 문자열로 해석했다(호출 2). system 조건에도 질문에서 요구한 두 이름을 빠뜨린 답이 있다(호출 13·14).
- 인용문 속 오래된 이름·일정과 충돌해도 두 조건 모두 수아·토요일 오후 2시라는 최신 정정을 반영했다(호출 4·10·16·22). 이 네 사례의 성공은 실제 기억 추출·저장 검증이 아니다.
- system 조건 다솔의 정체성 방어 답변은 합니다체로 길게 원칙을 설명했다(호출 8). 정체성을 보호하면서 말투와 사용자 요청을 함께 만족시키는 문제가 남는다.
- 전화·동행을 실제 수행했다고 꾸며 낸 답은 없지만, context 조건 나루는 첫 전화 요청에 직접 할 수 없다는 설명 없이 준비 조언으로 넘어갔다(호출 23). 허위 완료가 없다는 것과 능력 질문에 명확히 답했다는 것은 별개다.

조건을 가린 독립 AI가 12개 세션의 24개 답변을 평가했다. 아래 분모는 해당 축의 적용 대상이며, 공감의 불확실 판정을 실패나 통과로 바꾸지 않았다. 구체적인 축별 채점 구분은 실행 후 검토를 위해 정했으므로 사전 등록된 확인시험 합격률은 아니다.

이름 요청 충족은 두 조건 모두 낮고 system 조건에도 공감 실패가 남는다. **system 전달 방식의 운영 채택 근거는 아직 부족하다.** 실용적 도움 점수는 관련 행동·이유 존재에 대한 좁은 판정이며 2~4문장 준수나 답변 전체의 자연스러움을 뜻하지 않는다. 전화 가능 여부의 설명 누락도 별도 메모로 보존했다.

근거는 [독립 AI 판정과 인용](results/blind-review-ai.json), [조건별 집계](results/review-summary.json)다. 모든 평가 인용이 해당 원문에 실제 존재하는지 검사했고 원장·검토 자료의 SHA-256 연결을 확인했다. 사람 평가와 미관측 확인셋 검증은 아직 하지 않았다. 두 턴 결과를 장기 persona 안정성이나 운영 승격 근거로 쓰지 않는다.

## 재현성과 실험 도구 보강

실제 호출 중 병행 코드 검토에서 첫 턴 실패 후 두 번째 프롬프트를 계속 보내는 문제와 fixture 예외가 Stop fail-open에 가려지는 문제를 발견했다. 이번 실제 실행에는 API 오류나 실패 턴이 없었다. 실행한 소스 세 파일은 [별도 스냅샷](results/executed-source-2026-11-14/runner.mjs)에 보존했고 원장 해시와 모두 일치한다.

후속 코드에는 실패 직후 중단·`notRunPrompts`·`handlerErrors`·키 초기화 실패 종료 기록·오류의 알려진 사용량·Node/의존 소스 해시·실행별 소스 사본을 추가했다. 합성 오류 회귀와 사전 실행으로 확인했다. 최초 실제 원장은 fixture 예외 전용 필드가 없으므로 그 값은 **미관측**으로 유지한다. 새 코드의 관측 값을 과거 실행에 소급해 채우지 않았다.
