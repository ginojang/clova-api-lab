## K2의 별도 실행 준비 순서 — 아직 실행한 결과가 아님

1. Pi 대상을 `memory-lab/pi/cli.mjs`로 고정하고, 대본 전용인 옛 `harness-lab/pi`와 섞지 않는다. 기본 persona 정책과 모델·generation·도구·작업장·승인 결정·호출 한도를 고정한 새 계획을 만든다.
2. 기존 공통 파일 과제의 생성→수정→undo→read에 승인 거절·잘못된 인자/도구 실패·같은 응답의 여러 호출을 더해 양쪽에서 같은 산출물과 부작용을 확인한다. 모의 배선 검사와 실제 모델 시험은 별도로 기록한다.
3. `runCompleted`·`policyRejected`·`toolFailed`·`sideEffect`의 **실행기가 실제 보낸 값과 누락 여부**를 먼저 보존한다. 누락을 false로 채우지 않는다. `taskSucceeded`는 파일 내용·실행 흔적의 독립 판정이 있을 때만 기록한다. 거절 뒤 ok, 남은 호출 실행 여부, 도구 효과가 없었다는 근거를 따로 잰다.
4. 같은 실제 HCX에서 호출·usage·시간·오류·산출물·프로세스 정리를 비교하고, `costBasis:unknown`과 실제 0원을 구분한다. 결과가 없는 지금 기준선을 바꾸거나 전체 H1–H54 적합성을 선언하지 않는다.
