# H31 결론 — ② 운영 기본은 Elda CLI native

**이 랩의 H31 실행기 비교를 종료한다. ② 운영 기본은 코딩고래가 관리하는 Elda CLI native loop로 정리한다.** LangGraph는 회귀 비교 기준선으로 동결하고 H47/H48/H53 경고를 맞추는 개발을 추가하지 않는다. Pi는 ② 운영 후보에서 제외하고 memory-lab의 페르소나 실험에 한정한다. 다음 검증 대상은 실제 운영 Task `host-watch-explain`이다. 이 결론 자체가 운영 배포나 Task 실행 완료를 뜻하지 않는다.

| 근거 | Elda native | LangGraph | Pi |
| --- | --- | --- | --- |
| H31 2차 실제 과제·파일 판정 | 4/4 | 4/4 | 4/4, 당시 최종 응답 차단 별도 관측 |

| 역할 | ② 운영 실행기 | 동결 비교 기준선 | 페르소나 실험 |

H31 실제 요청은 합계91회다. 원래 실패와 계획을 보존하며 결과를 합쳐 하나의 성공률로 만들지 않는다. 마지막 실험의 5,999ms 간격 두 건은 그대로 미충족으로 남긴다. 실행기 선택을 바꿀 근거가 아니므로 이를 이유로 유료 재측정하지 않는다. 이 랩이 실행한 공식 키트는 당시 SPEC 본문0.808 전체를 검사하지 않는0.805 버전이며, 이 결과는 일반적인 모델 품질·성능 순위나 운영 전체 인증이 아니다.

**후속 키트 결과:** Elda-Spec `b888f05`의 kit0.808/harness0.809 기록은 CLI `4696537` + Ops `9731339`를 FAIL2/WARN1로 판정했다. H57의 notify `kind:human` 처리는 코딩고래, H61 `feed_read`·resource 누락은 인프라 담당이다. 수신 Comms `381c4a52dc`와 키트 README를 확인했으며 이 랩이 새 키트를 실행한 결과는 아니다. 위0.805 표로 최신 부적합을 덮지 않는다. 실행기 선택과 남은 계약 수정은 별개다.

**최신 수신 `c2810a7ec6`:** 인프라는 Ops `cf7138e`에 H61 도구·resource를 추가하고 mars 재측정에서 **FAIL1/WARN0**, 남은 항목은 H57이라고 보고했다. 이 랩이 배포 상태·새 키트를 직접 확인한 것은 아니며, H61을 계속 미수정 항목으로 요청하지 않는다.

**Elda CLI에 넘길 항목**

1. **429/42901 정책 점검:** 관측한 경로의 헤더는60 req/min·60,000 tok/min이었다. 다른 작업의 사용량은 통제하지 않았으므로 계정 전체 한도나 원인을 단정하지 않는다. 현재 CLI에는 도구 실행 전 한 번 재시도와 Retry-After 처리가 이미 있다. HTTP200/본문42901 경로의 대기 헤더 누락, 40080 분류·구조화 코드 차이는 모의 재현했다. 속도 조절과 함께 [인계 문서](NATIVE-HANDOFF-2026-11-11.md)의 근거로 소유자가 판단한다.
2. **원시 인자 경계 유지:** native의 숫자 text42 차단은 기존 모의 native transport 시험으로 이미 확인했다. 이를 미검증으로 남기거나 같은 확인을 위해 유료 호출하지 않는다. 별도로 빈 properties에서 additionalProperties:false 검사가 누락되는 함수 수준 반례는 인계한다. 임의 MCP 스키마 전체의 적합성을 보증하는 시험은 아니다.
3. **H57 알림 출처 경계:** 새 키트에서 드러난 notify `kind:human`은 화면의 사람 입력과 구분하도록 CLI 소유자가 보완한다. H61은 CLI 결함이 아닌 Ops MCP 소유 범위다.
4. **운영 결과의 근거 규칙:** `host-watch-explain`의 사실·수치·누적/증분·미상 구분을 실제 Task 경로에서 평가한다. 기존 system에도 사실 제한 규칙이 있으므로 부족한 부분만 소유자에게 제안한다. 과거의 계산 “4” 사례는 수신 보고이며 이 랩이 직접 재현한 결함으로 표시하지 않는다.

운영 Task·프로필·mars 실행은 인프라, CLI 수정은 코딩고래, CLOVA 응답 품질·토큰·오류 근거는 클로버가 맡는 방향으로 준비한다. [운영 시험안](../ops-task/HOST-WATCH-PLAN-2026-11-11.md), [페르소나 v8 인계](../../memory-lab/PERSONA-V8-HANDOFF-2026-11-11.md)를 분리했다. 페르소나 후속 실험 방향은 PRSN 팀과 조율한다.
