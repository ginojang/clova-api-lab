# Cycle 4 — H20+ 수정과 H31 준비

실행 전 계획: H20+ HTTP 200 본문 실패의 코드·apiError·retryable을 두 호환 경로에 보존한다. 오류 본문은 전달하지 않는다. 잘못된 코드도 502로 바꾸지 않는다. 오류 주입은 loopback 모의 공급자만 사용한다.

실제 API는 HCX-005/007 각 1회, 총 최대 2회로 정상 경로를 확인한다. 출력 상한128, 도구0, provider 재시도0. 성공 조건은 비어 있지 않은 답변·stop·유효한 usage다. 실패도 보존하며 이는 H31 및 페르소나 평가가 아니다. 기존 실험 원장에 소급 합산하지 않는다.

H31 대상은 Elda CLI native loop·LangGraph·memory-lab Pi다. 공통 과제는 파일 생성→수정→undo→read, 첫 호출 거절 후 후속 호출 차단, 두 호출 모두 승인, 잘못된 인자이다. 같은 모델 HCX-005·temperature0·출력2048·도구 schema·system 지시·승인·작업장 초기 상태·한도로 비교해야 한다. 파일 내용과 실행 횟수로 과제 성공을 판정한다. 비용 미상은 0으로 채우지 않는다.

현재 비교 전 확인: PATH의 elda는 오래된 진입점이다. 설치 디렉터리와 mars의 최신 Elda CLI를 구별해야 한다. ops 프로필은 Python MCP와 운영 지시문을 기본으로 사용한다. 랩은 Node MCP이며 Pi는 별도 페르소나 지시·메모리를 조립하므로 현재 기본값 그대로 비교하면 고정 조건이 다르다. 우선 프로필과 실제 wire 요청을 동등하게 고정해야 하며, 이 단계 없이 3경로 실호출을 H31 결과라고 부르지 않는다.
