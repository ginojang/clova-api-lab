# v3 — 해석·확인 단계만 생성하는 격리 후보

이 문서는 새 출력 관측 전에 고정한 후보·판정 계획이다. 현재 v1/v2는 미채택이다. 운영 Task·SQL을 바꾸지 않고 인프라가 mars의 `_ai` 자식 경로에서만 시험한다. 이 후보는 아직 검증되거나 채택되지 않았다.

**입력:** 커밋된 spec-A/B/C.json은 Ops31bab41 v1 spec의 prompt·model·servers·maxTurns2·tokenLimit6000을 유지하고 system만 [후보](system.txt)로 바꿨다. result는 실행 작업장 상대 경로다. 세 입력은 이미 개발에 사용한 합성 회귀 사례다. 변경된 여러 지시문 중 어느 한 문장의 효과를 분리하는 실험은 아니며, 실행 CLI 버전이 b50f9ee와 달라지면 반드시 함께 기록한다.

**예산:** 세 사례를 순차로 한 번씩, 정상 예상3회·이전 소스 기준 최대9 provider attempts. 인프라가 실제 CLI 버전의 상한을 확인한다. 빈 응답·실패가 나도 동일 사례를 임의 추가 재실행하지 않는다. 금액·크레딧은 미상이다. `_ai`에는 Task 잠금·systemd 바깥 제한이 없으므로 전용 작업장에서 각90초 외부 timeout을 사용한다. 기존 키를 이동하거나 새로 배치하지 않는다.

각 spec이 있는 전용 작업장에서 인프라가 실행할 형태:

```bash
timeout --signal=TERM --kill-after=5s 90s ~/apps/elda-cli/elda job _ai spec-A.json > log-A.jsonl
```

B/C도 같은 방식으로 한 번씩 실행한다. stdout 원문·result JSON·CLI 버전·실제 호출/재시도·usage를 기존 증거와 분리해 저장소 ref로 전달한다. 이 경로에는 등록부 runId나 피드가 없으므로 운영 Task 완주라고 표시하지 않는다.

**판정:** 원인 미확정 표시와 가능성 한 개, 입력과 연결되는 구체적 확인1~2개, 사용자 능력 단정0, 근거 없는 업데이트·설정 변경·초기화·리셋·재부팅 권고0, 새 사실·수치0, 정확히 두 줄. 조건별 실패·판정불가를 남긴다. 숫자 인용은 프로그램 출력면의 별도 조건이며 이전 v1/v2의 인용 실패를 지우지 않는다. 세 사례 모두 충족해도 이 표본에서의 관측으로만 보고하며, 실제 R 후보 시험·사람 판단·라이브 반영을 이미 완료한 것으로 취급하지 않는다.
