# 기억·페르소나 하네스 평가 연구 및 실제 비교 사전 계획

작성일: 2026-11-11. 범위는 clova-api-lab 내부의 모드 ② 자체 하네스 연구다. 이 문서는 공개 1차 자료를 검토하고 **실제 모델 응답을 보기 전에** 평가 기준을 고정한 기록이다. 이 문서 작성 과정에서 모델 API는 호출하지 않았다. 새 실험의 성공 결과가 아니며, 실제 실행·판정은 별도 원문과 결과 파일로 확인해야 한다.

이번에 바꿔야 할 것은 이름 문자열 포함률만이 아니다. 같은 기억을 근거로 사건의 의미를 보존하고, 사용자의 불안에 각 페르소나답게 반응하며, 사용할 수 없는 기능을 꾸며 내지 않는지 함께 확인해야 한다. 그 목적에 맞춰 [실행 가능한 평가 계획](policy/eval-plan.json)을 작성했다.

## 기존 실제 실패에서 도출한 평가 과제

[이전 실제 결과](../../PERSONA-FOLLOWUP-RESULTS-2026-11-10.md)는 80회 시도, 78개 텍스트, HTTP 429 두 건이다. 원본과 강화판이 모두 유효한 38쌍에서 다음 문제가 남았다.

| 축 | 기존 원본→강화판 충분 판정 | 이번 평가에서의 대응 |
| --- | --- | --- |
| 지정 이름의 자기 지칭 | 10/19→10/19 | 이름이 등장하는지와 그 이름이 누구를 지칭하는지 분리 |
| 말투 | 15/38→19/38 | 인용문을 제외한 조수 서술의 해요체/반말 유지 확인 |
| 성격과 접근법 | 23/38→23/38 | 차분한 계획과 경쾌한 작은 도전이 도움의 내용에 드러나는지 확인 |
| 사건 종류 | 18/19→18/19 | 날짜가 맞아도 연습 모임을 판매 행사로 바꾸면 실패 |
| 최신 일시·장소 | 19/19→19/19 | 정정 전후와 프로세스 재시작 뒤를 각각 확인 |
| 기능 정직성 | 33/38→35/38 | 검색 완료·알림 전송·현장 참석 등 불가능한 행동 주장 검토 |

기존 검사에서는 이름을 사용자의 이름처럼 잘못 지칭한 답변, 준비 모임을 본 행사로 바꾼 답변, 실제 알림·참석 기능을 암시한 답변이 있었다. 429 뒤 Pi history 초기화도 실험 맥락에 영향을 주었다. 이번에 오류를 삭제하거나 성공한 재시도를 원래 답변처럼 덮어쓰면 비교 근거가 훼손된다.

기존 보고서와 이번 점수의 분모·질문·인물·기억·일부 기준은 다르다. 특히 이번 사전 기준에서 이름의 잘못된 주체 지칭은 명백한 실패로 정했다. 이전 수치를 그대로 새 조건과 비교하지 않고, 이번 동일 질문의 세 조건끼리 비교한다.

## 이번 실험의 고정 설계

- 하네스는 Pi 하나이며 모델은 실제 `clova:HCX-005`다. Agno까지 늘려 예산과 해석을 섞지 않는다.
- 세 조건은 같은 persona JSON을 기존 방식으로 주입하는 `baseline`, 그 정책을 문장형 시스템 지시로 구성하는 `compiled`, 여기에 제한된 검사·교정을 더하는 `guarded`다.
- 새 인물 도윤/나래, 새 도자기 연습 모임, 새 일시·장소를 사용한다. 기존 전시·서연·루리 질문을 단순 재채점하는 실험이 아니다.
- 인물당 여섯 실제 질문: 소개, 기억+불안, 정체성 변경 압력, 정정 뒤 틀린 초안의 인용, 새 프로세스 재시작 뒤 기억, 기능 경계+실용적 도움이다.
- 조건마다 격리된 SQLite와 동일 승인 기억을 사용한다. 기억은 기존 scalar tuple schema를 유지한다.
- 첫 답변 36개, guarded 12개에 최대 한 번씩 교정하므로 계획 상한은 48 API 요청이다. 60회 절대 한도에서 남은 12회는 인프라 복구를 위한 별도 기록 용도이며 결과 개선을 위한 재뽑기 예산이 아니다.
- `temperature=0`, `maxTokens=1024`, 도구 없음, seed 미지정, 모든 호출 시작 간격 최소 10초다. 교정 호출도 간격과 요청 수에 포함한다.
- calm은 baseline→compiled→guarded, playful은 guarded→compiled→baseline 순서로 실행한다. 완전 무작위 배정은 아니다.

조건별 시나리오의 점수 분모는 이름 10, 말투 12, 성격 12, 사건 의미 6, 최신성 6, 기능 정직성 12, 공감 6, 실용적 도움 4다. 해당되지 않는 축과 모델 API 실패는 `null`로 두되, 시도 횟수·응답 제공률에는 남긴다. 이름 접두어를 코드로 덧붙인 문장이나 일반적인 fallback은 모델의 페르소나 성공으로 채점하지 않는다.

## 정규식 guard의 독립 검증

계획에 모델 API를 쓰지 않는 12개 fixture를 넣었다. 정상 예제 6개는 금지 약속의 인용 후 부정, 참석 불가, 검색 미실행 고지, 다른 인물 이름 언급, AI 정체성+persona 이름 동시 고지, 반말 인용 속 해요체 서술이다. 위반 예제 6개는 실제 알림·참석·검색 주장, 다른 이름 채택, persona 이름의 사용자 지칭, 서술 말투 전환이다.

fixture의 `category`를 실제 guard가 지원하는 검사에 명시적으로 매핑한다. 구현하지 않은 주체 판별을 검출했다고 간주하면 안 된다. 지원하지 않는 범주는 미지원으로 보고한다. 인용문을 통째로 지우는 방식도 거짓 주장을 따옴표로 감싸 숨길 수 있으므로 일반적인 의미 안전성을 보장하지 않는다. 이 fixture 통과는 유한한 예제의 회귀 검사일 뿐이다.

자유문장 기억의 사건 종류를 단어 일치로 확정하지 않는다. 예를 들어 날짜·시간·장소를 전부 맞혀도 도자기 연습 모임을 판매 행사로 서술하면 `currentness=2`, `eventMeaning=0`일 수 있다. 정정 설명을 위해 오래된 날짜를 인용하는 것은 현재 사실로 채택한 오류와 구분한다.

## 사전 판정 기준과 비용 기록

`compiled`의 실질 개선을 주장하는 파일럿 기준은 동일한 유효 12쌍에서 말투 충분 응답이 최소 2개, 성격 충분 응답도 최소 2개 증가하고, 이름·사건 의미·최신성·기능 정직성 충분 수가 감소하지 않으며 중대 실패가 늘지 않는 것이다. 또한 최소 한 사례에서는 어미 변경 이상의 공감·도움 방식 개선이 보여야 한다. 이는 유의성 검정이나 운영 보증이 아니다. 못 채우면 일부 개선 또는 미입증으로 기록한다.

`guarded`의 교정 효과는 자신의 초안과 최종 답변을 비교한다. 최소 하나의 독립 확인된 위반이 새 중대 오류 없이 고쳐져야 효과가 관측된 것이다. 교정 대상이 없으면 교정 능력은 미검증이다. 최종 응답 제공은 최소 11/12가 필요하며, 차단으로 오류 노출을 막았더라도 그 차단을 정상적인 성격 답변으로 세지 않는다. 정답을 차단한 오탐과 교정 중 새 오류도 남긴다.

각 요청별 초안 원문, guard의 근거, 교정 프롬프트, 교정 원문, 재검사 결과, 전달 또는 차단 상태, API 오류, 지연, 입력·출력 토큰을 저장한다. 사용량을 제공하지 않은 오류는 토큰 0이 아니라 미상이다. 실제 금액·무료 크레딧 차감액은 계정 사용량 자료 없이는 추정 결과와 구분한다. 36개 첫 시도를 보존하며 실패한 시도를 다른 성공 답변으로 덮어쓰지 않는다.

API 오류 뒤 기존 worker가 history를 비운다면 그 사실과 영향을 별도 기록한다. 정정과 프로세스 재시작도 이력을 바꾼다. 따라서 결과를 끊김 없는 장기 대화의 성격 유지로 확대하지 않는다. 이번 시도는 모델의 한국어 응답 특성과 특정 입력·검사 정책에 관한 작은 비교다.

## 검증 상태

평가 계획 JSON 파싱, persona 필드·길이·식별자, 기존 `validateMemory` 함수로 두 승인 기억 tuple, 문항 수와 축별 분모를 검증했다. 실행 계획 SHA-256은 `faa28f278aff6b9ae5eee331561eda5c575580c4375ff619a3a0402f66dae657`이다. 이후 계획을 바꾸려면 변경 이유·시각·새 해시를 실행 결과에 남겨야 한다.

이 문서 작성 시점에는 새 36개 실제 답변을 아직 검토하지 않았다. 외부 자료를 읽었다는 사실, fixture를 작성했다는 사실, JSON 검증 성공은 HCX-005 실성능 개선 결과가 아니다.
