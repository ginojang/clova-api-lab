# PRSN 논의용 기존 응답 8건

PRSN의 최신 정정(`f889ca0b35`)에 맞춰 **가벼운 배경 자료만** 모았다. 새 평가 정책·채택 기준·사람 승인 절차·고정 gold를 만들지 않는다. 모델 추가 호출은0회다.

[8건 원문 JSON](discussion-samples-2026-11-11.json)에는 전체 사용자 질문·응답·페르소나 정본·활성 기억, 실제 생성 rawDraftContent, 기존 주/보조 평가를 그대로 복사했다. 각 자료의 경로·JSON pointer·SHA-256으로 원본을 찾을 수 있다. `newAdjudication:null`이며 여기서 새 점수를 매기지 않았다.

## 고른 사례

점수는 과거 AI 평가의0/1/2 척도다. 두 칸은 주/보조 순서이며 사람 확정 점수가 아니다.

| DISC-02 | v8 확인의005 baseline · 성격 | 2 / 1 | 이름과 실제 반말은 유지했지만 일반 격려만으로 성격이 충분한지 갈린다. 말투를 바꾸겠다는 선언과 실제 말투도 구분한다. |

ID의 전체 형태는 JSON의 `PRSN-DISC-01`~`08`이다. 주·보조 평가의 모든 축과 근거 문장도 JSON에 보존했다. 위 표는 초점 축만 보여 주며 유리한 축으로 전체 평가를 대체하지 않는다.

## 범위와 해석

이8건은 기존344회 기록 전수를 다시 평가한 결과가 아니다. composed/confirmation/v9/v10/v11의 다섯 자료 묶음에서 불일치·오류를 목적에 맞게 골랐고, 같은 회상 질문의 정상 응답 한 건을 함께 넣었다. 따라서 이 묶음의 비율로 모델 품질이나 개선률을 계산하지 않는다.

**이미 개발에 노출된 사례**다. 과거 결과와 평가가 지시 개선에 사용됐으므로 미노출 holdout이나 새 성능 검증 세트가 될 수 없다. 지금은 사례를 함께 읽고 축의 차이를 논의하는 자료다. 이후 미노출 검증이 필요해지면 새 질문·배정 절차를 별도 논의할 수 있지만 이 문서가 이를 의무화하지 않는다.

정본 이름을 렌더러가 넣는 방식은 제품 출력의 이름 안정성에 대한 별도 선택이다. 여기의 원문은 모델이 만든 이름을 포함하므로 렌더링 보정 사례로 바꾸어 기록하지 않는다. 이름 칸이 안정된 것과 모델 자체의 정체성 유지 능력은 서로 다른 관측이다.

## 모델 하나만 바꾸는 비교의 현재 제약

현재 랩 [모델 설정 코드](../../clova/clova-model-config.ts)는 `responseFormat`을 HCX-007에만 허용한다. [composed-v8](../policy/composed.mjs)은007에서 사용한 native JSON 계약에 기대고 있다. 따라서 “005에 v8을 그대로”는 현재 코드 계약과 바로 맞지 않는다. 이는 새 제공자 시험 결과가 아니라 **로컬 구현 사실**이다. 모델 호환성을 확인하지 않은 채 JSON 계약을 빼면 모델과 계약 두 변인이 함께 바뀐다. 이번에는 제공자 조회·유료 재현·구현 변경을 하지 않았다.
