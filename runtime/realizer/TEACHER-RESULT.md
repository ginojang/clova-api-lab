# HCX-005 선생 자료와 슬롯 검사 — 2026-11-11

**원문을 검수 없이 학습 정답으로 쓰기 어렵다.** 자연스럽게 읽히는 문장에서도 수치 누락, 부정의 의미 변경, 새 평가/감정/근거가 발견됐다. 아래 결과는 선생 생성 실험이며 작은 학생 모델의 품질 시험이 아니다. 학습과 운영 반영은 하지 않았다.

## 생성과 전송 형식

고정 [계획](PLAN-2026-11-11.md)은 20개 의미 골격 × 3말투 × 2표현 =120쌍이다. [fixtures.json](fixtures.json)은 최초 호출 전 `52a6818`에 고정했다. 각 입력에 명시적 의미 문장·슬롯·술어를 제공했고 작성한 fallback 문장은 모델에 주지 않았다. 이 시험은 불완전한 키워드에서 의미역을 추론하는 능력 시험이 아니다.

`clova:HCX-005`, temperature 0, maxTokens 2048, 도구 0, 묶음당 12행으로 요청했다. 최초 10회와 형식 오류 재시도 6회, **총 16회**로 종료했다. 프로젝트 상한은 50회이며 추가 호출하지 않았다. 응답에 기록된 사용량은 입력 **16,509**, 출력 **5,157**, 합 **21,666 tokens**다. 금액·실제 청구액·cache hit는 확인하지 않았다. 클라이언트 시도 수와 응답 사용량이며 제공자 결제 원장 대조는 아니다. [모든 요청·응답·사용량](results/teacher-v1-2026-11-11/report.json)

최초 응답만 사용한다는 기준으로 전송 형식을 따로 정리했다. 재시도에서 의미가 좋은 문장을 고르지 않았다.

## 기계 검사와 독립 AI 검토

고정 슬롯 검사기 통과는 **55/108=50.9%**, 최초 계획 대비 **55/120=45.8%**다. 이 값은 의미 보존률이 아니다. 모든 결과에 `semanticReviewRequired=true`가 남는다. [실제 검사 원문](results/teacher-v1-2026-11-11/slot-check.json)

[평가 기준](REVIEW-RUBRIC.md)에 따라 두 AI가 다른 평가와 기계 집계를 보지 않고 108행을 각각 읽었다. 원문·판정 사유는 [평가 A](results/teacher-v1-2026-11-11/review-a.json), [평가 B](results/teacher-v1-2026-11-11/review-b.json), 재계산 가능한 [합산 결과](results/teacher-v1-2026-11-11/evaluation-summary.json)에 있다. 각 항목의 통과 수, 두 판정 일치도, 불일치 ID, 불확실성을 제외한 교집합을 저장한다. 합산기는 평가자의 수기 합계를 신뢰하지 않고 행별 boolean에서 다시 센다.

| 평가 축 | A 통과 /108 | B 통과 /108 | 두 평가의 판정 일치 |
|---|---:|---:|---:|
| 의미 보존 | 46 (42.6%) | 47 (43.5%) | 103/108 (95.4%) |
| 말투 일관성 | 81 (75.0%) | 70 (64.8%) | 95/108 (88.0%) |
| 자연스러움 | 100 (92.6%) | 100 (92.6%) | 106/108 (98.1%) |
| 세 항목 통과 + 불확실성 없음 | 31 | 30 | 두 평가의 보수적 교집합29 |

각 평가의 어색한 문장 수는8/108(7.4%)이지만 해당 ID가 완전히 같지는 않다. 불확실 표시는 A22개/B25개다. **두 AI 모두 세 항목을 통과시키고 불확실성이 없는 문장은29/108=26.9%, 계획120행 대비24.2%**다. 말투별로 다정5/36, 무뚝뚝16/36, 사극8/36이다. 말투 판정13건 등 불일치를 합의로 덮지 않았다. 이 29개도 사람 검수가 끝난 학습 정답이라는 뜻은 아니다.

기계 어휘 검사에 통과한55개 중 **21개는 두 AI 모두 의미 보존 실패로 판정**했다. 이 수는 AI 판정과의 불일치이며 사람 정답 기준의 검사기 오수락률이 아니다. 어휘 검사 통과가 의미 전체 보증이 아니라는 실제 사례를 보여준다.

두 평가는 사람 정답이 아니며 다른 모델 계열의 독립성도 보장하지 않는다. A는 앞서 fixture/검사기를 작성했으므로 완전한 설계자 블라인드가 아니다. 같은 골격의 말투·변형은 서로 종속된다. 이 작은 표본으로 실제 서비스의 전체 성공 확률이나 성격 전체 유지 능력을 추정하지 않는다.

## Fallback과 채택 범위

기계 검사 실패/누락에 작성해 둔 fixture 틀 문장을 쓰면 **65행이 대체**, 최종 어휘 검사120/120이 된다. 모델 원문 어휘 통과는 여전히55/120이며 의미 승인 수는0이다. 이 결과를 “생성 성공률100%”로 쓰지 않는다. 어휘 검사를 통과한 의미 오류는 그대로 남을 수 있다. [대체 결과와 원문 집계](results/teacher-v1-2026-11-11/fallback.json)

독립 AI가 모두 동의한 문장도 이후 사람 검수의 후보일 뿐 확정 학습 데이터로 승격하지 않았다. 다음 데이터 단계에서는 의미 골격 family로 train/dev/test를 나누고, 이름·수치·부정·소유·요청/완료 최소쌍을 넣는다. 이 파일럿을 설계에 사용했으므로 새 학생 모델의 독립 test로 재사용하지 않는다. [학습·제어 계획](research-control-training.md)

## 재현

아래는 저장된 원문을 다시 평가하는 **추가 API 호출 없는** 명령이다. `check`의 exit1은 실제 데이터의 실패/누락을 발견했다는 뜻이다.

```bash
python3 -B -m unittest discover -s runtime/realizer/tests -v
python3 -B runtime/realizer/extract-first-attempt.py runtime/realizer/results/teacher-v1-2026-11-11
python3 -B runtime/realizer/slot-check.py check runtime/realizer/results/teacher-v1-2026-11-11/samples-first-attempt.json --report runtime/realizer/results/teacher-v1-2026-11-11/slot-check.json
python3 -B runtime/realizer/slot-check.py fallback runtime/realizer/results/teacher-v1-2026-11-11/samples-first-attempt.json --output runtime/realizer/results/teacher-v1-2026-11-11/fallback.json
python3 -B runtime/realizer/summarize-teacher.py
```

`generate-teacher.ts`는 기본 dry-run, `--live`를 붙여야 실제 호출한다. 재시도도 호출 상한에 포함하며 `.local/realizer-teacher-budget.json`의 누적16회 기록을 보존한다. 이 파일을 지워 새 예산으로 취급하지 않는다. 현재 과제의 선생 생성은 종료됐다.
