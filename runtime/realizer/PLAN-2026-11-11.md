# 초소형 한국어 문장 다듬기망 — 조사·검증 계획

요청 근거: 풀스택 Comms `8b674818d0`. 기존 게임/에이전트의 제한된 표현 단계에서 큰 API 두뇌를 대신할 현실적인 선택인지 조사한다. 학습·운영 반영은 하지 않는다.

- 자료: 선행 surface realization/data-to-text, 공개 한국어 소형 seq2seq, 토큰 표의 크기, 라이선스, 브라우저·CPU 실행 조건을 1차 출처로 확인한다. 가중치의 이론 크기와 실제 배포 파일 합계를 구분한다.
- 선생: `fixtures.json`의 의미 20개 × 다정/무뚝뚝/사극 × 2표현 =120쌍. `generate-teacher.ts`는12개씩10묶음으로 HCX-005에 요청한다. temperature0·출력2048·도구0. 형식 오류/일시 오류만 묶음당1회 재시도하며 별도 프로젝트 원장으로 **최대50요청 시도**를 막는다. 의미가 나쁜 답을 재생성해 숨기지 않는다.
- 입력은 명시적 의미 문장과 typed slots/술어다. 검사기 대체 문장은 선생 입력에서 제외한다. 이 검사는 키워드만으로 의미역을 복원하는 능력이나 작은 학생 모델의 품질을 입증하지 않는다.
- 평가: 원문을 바꾸지 않고 슬롯 검사기와 두 독립 AI 검토를 병행한다. 이름/수치 보존, 시제·부정·요청/완료, 말투, 자연스러움과 새 사실을 분리한다. 사람 평가의 대체나 통계적 일반 성능으로 과장하지 않는다. 중복 문장과 파싱 실패도 센다.
- 대체 문장: 슬롯 검사 실패 때는 작성해 둔 의미 보존 틀 문장을 반환한다. 이것은 모델의 통과가 아니라 프로그램의 복구이며 원문·실패 이유를 보존한다. 어휘 검사 통과가 의미 전체 보장을 뜻하지 않는다.
- 실측: 현재 작업 호스트는 **pluto, Xeon E5-2640,24 logical CPU,약31GiB RAM,AVX 있음/AVX2 없음**. 자기 폴더의 격리 Python 환경·캐시에만 설치/다운로드한다. 공개 모델1~2개를 ONNX로 변환·동적 int8 양자화하고 파일 실제 bytes, load/warm encode+decode 지연, 출력 토큰 수·스레드 수를 기록한다. 학습은 하지 않는다. 미학습 모델 출력은 품질 근거로 쓰지 않는다.

브라우저/모바일 지연은 직접 측정하지 않으면 미측정으로 남긴다. 모델+토크나이저+여러 ONNX 그래프의 중복·캐시·런타임 부담을 포함해 10~50MB/문장당 수십 ms 목표와 비교한다. 학습 데이터 양·시간·GPU는 제안만 작성하고 실행하지 않는다.
