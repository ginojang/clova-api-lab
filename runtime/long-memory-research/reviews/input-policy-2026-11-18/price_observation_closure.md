## 남은 두 관측 경계

**전체 턴 분모.** 가격 판정은 :350에서 선행 시작하지만 가격 로그는 `else if (decodeEnabled())`(:1296) 안의 :1326에 있다. 앞의 risk_floor 거절, 이미지 응답, nearest 응답, deterministic 페르소나 분기(:1249–1295), decode 비활성, `input_too_long` 조기 종료(:400–411)는 이 위치를 지나지 않는다. 정체 고정 응답 가지는 idAsk=null(:1069)이라 현재 실행 가능한 누락 사례에 넣지 않았다. 블록 생성 등 로거 이전의 예외도 기록을 막을 수 있다.

따라서 현재 이벤트의 분모는 **decode의 가격 결정 위치에 도달해 로그를 남긴 기능 on·사람 턴**이다. 로그 부재를 no/unknown으로 채우거나 전체 판정 요청 수로 쓰면 안 된다. 미호출 null은 값으로 분리됐지만 생성·로깅 guard가 동일하므로 안정된 설정에서 기능 off/nonHuman은 이 이벤트의 분모 밖이다.

담당 후속은 현재 분모로 관측 계약을 좁히거나, 실제 전체 on·human 분모가 필요하면 응답 경로 종료와 판정 시작을 연결해 미소비·조기 종료도 기록하는 것이다. 후자를 택하더라도 로그를 위해 모델 판정을 다시 호출할 필요는 없다. 이는 설계 제안이며 클로버가 서빙 코드를 구현하지 않았다.

**`skip=null`의 뜻.** :1322–1325에서 null은 elda·지도 replace 아님·yes·기존 가격 근거 없음 조건 통과다. 다음 상태가 모두 가능하다.

| skip | ledger | built | assembled_into | 의미 |
|---|---|---|---|---|
| null | empty 또는 error | false | null | 조회를 시도했지만 추가 블록 없음 |
| null | ok | true | suppressed_by_care | 블록은 만들었으나 위기 돌봄 때문에 추가 주입 제외 |
| null | ok | true | messages 또는 consult+messages | 해당 조립 경로를 선택함 |

마지막 행도 최종 모델 수신/응답 성공 영수증은 아니다. 이벤트는 `buildMessages`(:1331)보다 앞에 기록된다. 수신의 “null=실음” 설명은 “조회 전 조건 통과”로 정정하고, 데이터·블록·조립 상태를 함께 읽어야 한다. 소소한 문서 잔여로 :348의 옛 “엘다 턴만” 주석도 바로 뒤 실제 선행 호출 설명과 맞추면 된다.
