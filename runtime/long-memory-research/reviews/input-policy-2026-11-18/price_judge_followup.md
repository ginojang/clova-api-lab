## 남은 관측·설명 차이

1. **호출과 주입의 범위가 다르다.** 자산 주석은 elda·RAG 가격 없음일 때만 묻는다고 설명하지만 시작 조건은 기능 on인 모든 nonHuman 제외 턴이다. elda가 아닌 턴, 이미 가격 근거가 있는 턴, 지도 replace 턴에도 판정이 먼저 시작될 수 있다. 소스상 추가 호출 가능성을 확인한 것이며 실제 발생 수·비용은 미측정이다. 의도한 선행 호출이라면 주석을 맞추고, 그 범위가 불필요하면 이미 아는 자격 조건부터 제한할 수 있다.
2. **no/unknown/미호출은 주입 정책상 닫히지만 호출자 관측에서는 충분히 구분되지 않는다.** `asksPriceP`는 모델 stamp·unknown 이유를 버리고 verdict만 전달한다. 기능 off/nonHuman도 unknown이고, 소비 대상이 아니면 `askPrice`도 unknown으로 덮는다. `chat.price_summary`는 yes+기존 근거 없음 분기 안에서만 찍히므로 no, unknown, 미호출, 기존 근거 있음의 생략 이유를 이 로그로 분모화할 수 없다. 로그 없음은 no 판정의 증거가 아니다.
3. **공통 judge 기록은 보완 근거일 뿐 모든 턴의 결정 기록이 아니다.** 정상 no/unknown은 공통 경로의 로그·표본 대상이지만, 표본은 pool·수집 설정·DB 성공에 의존하며 캐시 적중은 새 표본을 쓰지 않는다. 이번 호출은 turnId를 넘기지 않는다. 자산 로딩 예외처럼 공통 결과 생성 전에 실패하면 호출자의 catch가 unknown으로 받지만 공통 표본 생성은 보장되지 않는다. 이는 기존 공통 코드의 한계이며 새 고객 키워드 fallback은 아니다.
4. **S1 품질이나 원격 자산 등록은 확인한 것이 아니다.** 새 이름이 S1 계약·축·소비자에 추가된 변경은 없다. 공통 judge가 로컬 직접 경로를 쓰면 로컬 자산 본문이 모델 입력이고, JUDGE_DOOR_URL 경로면 ask/text만 전송한다. 운영 설정은 읽지 않았으므로 선택된 경로의 자산 준비는 별도 실행 증거가 필요하다. 기존 공통 YES/NO 파서의 허용 범위·door stamp 검증 한계도 이번 커밋에서는 바뀌지 않았다.

최소 후속 제안은 결과 객체의 `verdict/source/unknown_reason/model/prompt_ver`를 보존하고, 미호출은 별도 상태로 기록하며, 모든 가격 요약 결정에 `eligibility`, `rag_price_present`, `ledger_requested`, `block_built`, 최종 주입 결과와 생략 이유를 남기는 것이다. yes와 데이터 존재·실제 주입을 서로 다른 사실로 유지해야 한다. 이 제안은 본 감사에서 구현하지 않았다.
