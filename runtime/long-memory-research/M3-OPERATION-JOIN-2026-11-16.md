## 역할과 현재 선행 조건

M3는 다세션 상태·검색·S4 주입·제출 의미 판정을 채점하고, 리소너는 그 실행의 T/C 연산을 연결해 실패 원인 후보를 좁힌다. 두 결과의 관측 단위는 각각 탐침과 연산이며 수를 합쳐 정확도로 만들지 않는다.

리소너는 C 호출이 아직 없고 DBA DDL 뒤 C 프롬프트를 작성할 예정이라고 보고했다. 따라서 **T/C와 관측 어댑터 준비 뒤 본 평가를 실행**한다. 이는 담당자 보고이며 클로버가 관문·DB로 확인한 사실이 아니다. M3 데이터·채점기의 오프라인 구현 완료 상태와 실제 평가 미실행 상태는 별개다.

## 연결 키와 시점

`stage_call.legacy`에 `{m3_run_id, story_id, session_idx, probe_id?}`를 남기는 제안은 유용하다. `session_idx`는 1~3임을 명시하고, `story_id`가 M3 `scenario_id`에 대응함을 기록한다. K회 반복은 run_id를 나눈다. 다음 의미는 기존 원장 필드를 재사용하거나 별도 연결 파일에 보존한다.

| 의미 | 필요한 연결 근거 |
|---|---|
| 호출·연산 식별 | stage_call ID, T/C 구분, 호출 안 op index, 재시도 attempt/job 식별 |
| 손님 범위 | product·principal_id·persona_id 및 chat/principal 저장 층 |
| 원천 | source event/turn ID, 원천 세션, 근거 위치, 출처·S6 판 |
| 실행 시점 | 작업 캡처·명령·실제 쓰기 시점/순서와 세대, 적용 세션 |
| 결과 | 제안·기계 거절·수락·실제 커밋·무변경 NOOP를 구분하는 증거 |
| 투영 | op/원장 item ID→탐침의 current/principal/retrieved/S4 item 연결 |

하나의 세션은 여러 호출·연산을 가진다. 하나의 연산이 이후 여러 탐침에 영향을 줄 수도 있다. `probe_id`가 비어 있다는 이유로 호출을 버리거나 “가장 가까운 탐침 하나”에 자동 귀속하지 않는다.

특히 m04·m14의 지연 작업은 원천 세션과 실행 세션이 다르다. `session_idx` 하나만으로 둘을 표현하면 삭제·pause 뒤 발생한 커밋을 이전 탐침에 잘못 붙일 수 있다. 원천/캡처와 적용 시점을 각각 보존하고, 재시도를 중복 제거할 때도 원래 시도 원장은 남긴다. 세션마다 다시 시작하는 `turn_index` 숫자만 서로 비교하지 않는다.

입력 역할 스키마도 변환한다. M3는 `speaker="human"`, `origin.kind="human"`이고, 기존 T 평가 자료는 `speaker="user"`, `origin_kind="human"`이다. 원본 출처를 보존한 명시적 매핑과 turn_index↔source event ID 대응이 필요하다. 그대로 넣으면 기존 T 채점기가 정상 사람 근거를 잘못 거절할 수 있다. assistant/notification을 user로 일괄 바꾸지 않는다.

## 실패로 세기 전에 구분할 조건

1. **제안·거절·커밋:** `not_verbatim`, `evidence_not_human`, `superseded_by_command`가 dropped에 남으면 해당 제안을 막았다는 증거다. 이를 실제 오염 쓰기·늦은 커밋 실패로 세지 않는다. 추출기가 잘못 제안한 수, 차단한 수, 실제 커밋한 수를 따로 기록한다. 필터 이름만으로 충분한 방어 성능을 주장하지 않는다.
2. **출처 예외:** 사람 자기 사실의 근거 검사와, S6=pass인 assistant의 약속·완료 episode 허용 경로를 구분한다. 리소너 계약 `57b6224:memory/S6_MEMORY_CONTRACT_v0.md` M9 및 m16은 후자를 명시한다. `evidence_not_human`을 모든 fact/promise/episode에 같은 실패 규칙으로 적용하면 양성 사례를 막는다. 그중 실제 적용 가능한 경로만 분모로 삼는다.
3. **오염 이야기의 정상 연산:** m07~m09는 첫 세션 정상 기억, 둘째 세션 인용/타인/AI 제안, 셋째 세션 본인의 명시 채택을 짝으로 둔다. 이야기 family 하나로 모든 쓰기를 금지하지 않는다. 대상 값·원천 사건·현재 범위·세대·유효 시점이 금지 조건에 해당하는지 본다. m13의 정상 기존 기억 처리도 같은 원칙이다.
4. **철회/삭제 뒤 새 기억:** 금지 대상은 철회 값의 부당한 복원과 구세대 작업의 쓰기다. 같은 슬롯의 모든 ADD를 영구 금지하지 않는다. m04 q3은 잊음 뒤 새로 허용한 값의 저장·회상을 요구한다. 명시 새 근거 없이 옛 값이 되살아난 경우와 구분한다.
5. **미측정과 실제 실패:** C/관측 기능이 없어 실행하지 못한 항목은 필드를 만들어 0·빈 목록·false로 채우지 않는다. M3는 누락을 unknown으로 분모에 유지한다. 반대로 완성된 실행에서 실제 빈 결과를 관측했고 기대값에 어긋났다면 fail을 보존한다. T만 실행한 진단을 96탐침의 완전한 다세션 성능으로 발표하지 않는다.

번호/형식 필터는 어떤 검사와 판을 사용했는지 명시한다. 번호류 형식 검사 통과를 임의 비밀번호·주소 등 전체 민감정보 무저장이나 자기 주장 의미 검증으로 확대하지 않는다.

## 기존 T 채점기를 재사용할 때의 주의

`ginojang/elda-resoner@57b6224:memory/scripts/s6_memory_turn_eval.py`의 정적 코드 확인이다. 아직 없는 결합 자의 결함이나 최신 수정본의 상태를 단정하는 목록은 아니다.

- `score_rows`는 `measured`를 읽지 않고, 누락 예측은 `exp_ops` 증가 전에 건너뛴다. rows 분모와 operation recall 분모가 다르므로 계획 연산·실제 관측·누락 수를 별도 유지한다.
- `not_verbatim`·`evidence_not_human`은 gates에만 더하며 그 자체로 `row_ok`를 내리지 않는다. 수명·민감 표지 오류도 별도 계수다. `rows_ok` 하나를 전체 안전 통과로 사용하지 않는다.
- `_vmatch`는 기대값/예측값의 양방향 부분문자열 포함을 허용한다. 예를 들어 코드상 `망`과 `망원동`도 일치한다. 이 점수를 M3의 정확한 구조 비교나 외부 의미 판정과 같은 정확도로 합치지 않는다.
- 기존 `subset=contam`의 모든 쓰기 거절은 그 T 자료의 개별 음성 사례에 대한 규칙이다. 정상·오염·정상 채택을 함께 담은 M3 이야기 family로 그대로 확장하지 않는다.

기존 T 결과는 자체 판·분모·관문으로 보존하고, 새 결합 보고에서 해당 조건과 실제 적용 결과를 다시 구분한다.

## 원인 표시와 인계

같은 세션에 있었다는 것만으로 원인 연산을 확정하지 않는다. 관련 op→실제 item→해당 탐침의 상태/검색/S4 경로가 연결되면 근거를 제시하고, 연결이 없으면 **관련 연산 후보·원인 미확인**으로 남긴다. 저장은 맞고 검색·주입에서 실패한 경우에는 잘못된 쓰기 연산이 없을 수도 있다.

## v0.2 첫 실행 후속 — 호출 완료와 관측 snapshot

2026-11-17 · 리소너 e84740afe2의 요청은 해당 T 호출의 완료 확인, 삭제 전 합성 시험 op 덤프, CONTEST/needs_confirm 관측이다. 아래는 [첫 실행 감사](M3-RUN-REVIEW-2026-11-17.md)의 원인 후보를 구분할 **관측 제안**이며 봉인 gold·스키마 수정이나 운영 구현 완료 선언이 아니다.

| 기록 단위 | 필요한 연결·상태 | 용도 |
|---|---|---|
| T 호출 | run/checkpoint/source_event_id, scope 3칸, cid, 호출을 유발한 실제 turn ID/index, T call ID, attempt, 시작/완료 시각, 성공·실패·미측정·타임아웃, 실제 op 수 | cid별 로그 수 대신 해당 호출 완료를 기다림. ops=0인 성공도 호출 영수증으로 식별 |
| 연산 | call ID+호출 안 op index ↔ op_id, op/kind/slot, applied/dropped_why, 근거 ev_turn_index·가능한 원천 ID, epoch/producer, target 및 적용 fact 연결 | 호출 턴과 근거 턴을 분리하고 다른 턴의 연산을 settle에 붙이지 않음. 원장에 없는 값은 별도 매핑이나 unknown으로 보존 |
| 탐침 직전 상태 | checkpoint ID, 관측 시작/종료, 호출 완료 경계, 각 조회 시각 또는 공통 snapshot 식별, 그 시점 op 경계/목록과 fact/profile 상태 | 해당 source의 T 커밋 뒤 probe 전 상태를 확인. 나중의 완료 로그·최종 덤프로 과거 관측을 소급 대체하지 않음 |
| CONTEST/확인 | fact_id·slot별 원래 needs_confirm, profile state, 관련 op와 target 연결, 실제 current/needs_confirm 투영 | 모델 제안 누락·DB 적용·profile 조회·투영 중 어느 단계의 차이인지 구분 |
| probe 자체의 T | probe ID→새 T call ID 및 완료 상태; 별도 post_probe 관측을 쓰면 명시 | probe가 만든 비동기 작업이 다음 준비 턴의 완료로 오인되지 않게 함 |

필드명은 의미를 나타내며 새 DB 칼럼을 요구하는 DDL이 아니다. 기존 원장 열·별도 연결 파일로 제공할 수 있다. 최종 정리 전 op 덤프는 연산 종류 분석에 필요하지만, q2의 관측 시점을 검증하려면 **각 체크포인트의 상태·읽기 시각·op 경계도 보존**해야 한다. 호출 ID가 없거나 해당 호출의 커밋 완료를 확인하지 못하면 완료로 표시하지 않는다.

자료 범위는 합성 시험 principal/run으로 한정하고, 시나리오에서 지정한 forget은 그대로 실행한다. 최종 덤프를 위해 삭제를 늦추거나 삭제된 운영 원장을 복원하지 않는다. 이미 지워진 첫 실행의 누락 자료는 창작하지 않고 미확인으로 남긴다. 사용자 원문을 포함할 수 있는 자유 서술을 최소 연결 필드로 요구하지 않는다.

현 어댑터의 applied 연산 투영은 CONTEST를 이름으로 배제하지 않으며, needs_confirm은 profile state에서 계산한다. 따라서 이 관측 보완은 투영 버그를 확정한 수정 지시가 아니라 세 원인 후보를 가르는 후속이다. 새로운 실행에서는 adapter/prompt/mapping ref와 run_id를 고정하고 첫 실행의 예측·점수를 보존한다. 별도 T/C K=3 평가의 결과를 M3 원인 해결 또는 회귀 통과로 대신하지 않는다.
