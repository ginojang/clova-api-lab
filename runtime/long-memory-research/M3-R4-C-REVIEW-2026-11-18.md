## n14 — 계약 정합과 남은 근거 구간

리소너는 eval-v0 문장을 eval-v1 n14로 잘못 인용한 것과 골드 모순 주장을 철회했다. 기존 M5를 유지하므로 명시 대체는 SUPERSEDE, 단순 새 기본값 진술은 CONTEST라는 해석이 맞춰졌다. [r3 후속 대조](reviews/m3-v02-r3-2026-11-17/n14_policy_followup.json)는 당시 원문과 op539의 why를 보존한다.

r4 signage의 SUPERSEDE/ce_turn=3/ev_turn=3/내림0과 why는 기존 M5 기준 오판 분류를 뒷받침한다. 다만 **ce_turn은 원천 턴 번호이지 모델이 낸 정확한 CE 부분문장 자체가 아니다**. “기억해 줘”를 냈는지 값만 냈는지를 확인하려면 합성 실행 전용 원출력 또는 검증된 구간·입력 해시가 필요하다. 닫힌 단어 표 도입이나 봉인 gold 변경으로 이 문제를 처리하지 않았다.

## n08·n10 — C 응답이 밝혀 준 범위

[사례 원자료 대조](reviews/m3-v02-r4-2026-11-18/runtime_cases.md)에서 C 응답 8건을 별도 텍스트·캡처 c_runs·실행 사건과 연결했다. 다음 계수는 서로 다른 체크포인트의 연속 호출이며 동일 입력의 독립 반복이 아니다.

n08 guest의 C 세 번은 모두 약속 0이고 signage의 마지막 C는 약속 1을 냈다. signage의 약속 근거는 pass 턴9이며 적용됐지만, 같은 출력의 why는 확정된 약속이 아니라고 했고 p_yes는 0.15였다. 이 사례에서 p_yes를 높은 문턱으로 거르면 해당 약속도 사라진다. 리소너는 보정되지 않은 자기평가 수치를 새 저장 기준으로 삼지 않고 기록만 유지하기로 했다. 이를 p_yes 전체의 품질이나 일반적인 최적 문턱에 대한 검증으로 확대하지 않는다.

그런데 n08-signage q3의 점수는 계속 실패다. 봉인 gold가 기대하는 정확값은 “다음 방문에 창문 치수 재확인”이고 관측 effective_active_values/must_repeat_values에는 “창문 치수 재확인”이 들어 있기 때문이다. C 출력·적용 요약·새 customer_memory에는 긴 표현이 있는데 어댑터 harvest가 “다음 방문에”를 제거해 배열에 짧은 값만 남긴다. 답변도 다음 방문 때 치수를 확인한다는 내용을 담는다. 따라서 **점수 불변을 약속 저장 0개나 회상 불능으로 해석하면 안 된다**. 문자열 투영 경계와 의미 평가 부재를 보존하며 점수를 사후 보정하지 않는다.

초기 block 약속 뒤에 “제안일 뿐”이라는 중간 답이 있고 마지막 pass 재약속이 이어지는 이력은 시간 순서 규칙을 보완할 구체적 근거다. 다만 C 요청 전체와 통제 비교가 없으므로 그 중간 답이 누락의 유일한 원인이라고 확정하지 않는다. 출력의 자기설명도 독립적인 인과 증명은 아니다.

n10 첫 C의 raw는 양쪽 모두 episode:null이다. 따라서 **이 호출은 모델이 episode를 내지 않았고 해당 episode INSERT를 시도하지 않은 경우**로 구분된다. 이전 r3에서 남았던 미출력/INSERT 실패 모호함을 r4의 이 두 호출에 한해 줄였다. k2/k3 raw에 앞선 C 요약이 남아 있어도 추가 C 호출이 생긴 것은 아니며 advance_time taint로 유효 후속 탐침도 없다. “턴1뿐”은 관측된 assistant 원천/S6 맵 설명으로 읽어야 하고, 저장되지 않은 C 요청 전체가 한 턴이었다는 증명은 아니다.

## C v0.6~v0.8 — 원출력과 사후 재채점

[고정 출력 재채점](reviews/c-v07-v08-2026-11-18/REVIEW.md)은 프롬프트·골드·채점 코드와 출력 파일의 해시를 함께 보존한다. 각 숫자는 K=3의 반복별 행 통과 수이며, 서로 관련된 반복을 독립 사례 수로 늘리지 않는다.

| 실행/채점 조건 | 모델 원출력 | 후처리된 출력 | 의미 |
|---|---:|---:|---|
| C v0.006 × 자료 v0.6, 15행 | 14·15·14 / 15 | 14·15·15 / 15 | 세 번째 반복 p02의 fix 원천 did를 guard가 제거 |
| C v0.007 × 자료 v0.7, 18행 | 16·16·16 / 18 | 16·16·16 / 18 | d03/d04 episode kind 두 건씩 실패 |
| **같은 v0.007 출력** × 자료 v0.8 | 18·18·18 / 18 | 18·18·18 / 18 | 출력 열람 뒤 kind 라벨 두 곳 변경한 재채점 |

첫 행에서 제출 요약과 일치하는 것은 후처리 점수다. raw라는 파일 이름만으로 그 요약을 모델 원출력 자체의 점수로 부르지 않는다. v0.6 d01/d02의 약속은 6출력 모두 pass5이며 약속 누락은 재현되지 않았다. 남은 d02 첫 반복 실패는 kind다. v0.7의 원출력/후처리 관문은 모두 0이며, 기대 약속 7개는 각 반복에서 모두 잡혔다.

새 d03/d04는 앞선 “제안일 뿐” 뒤에 나온 pass 재약속을 세 번 모두 턴7에 연결했고, d05는 뒤에 철회한 약속을 세 번 모두 제외했다. 기존 13개와 v0.6 추가 2개, v0.7 추가 3개의 분모는 별도 집계했다. 이 자료는 이미 본 r4 실패를 바탕으로 만든 회귀 자료다. 새 규칙·why 지시·예시 변경이 함께 들어갔고 구 프롬프트를 같은 새 사례에 대조한 조건은 없으므로 특정 문구의 독립 효과를 측정한 것은 아니다. C v0.007의 M3 n08 실행 결과도 이번 자료에는 없다.

자료 v0.7→v0.8은 **d03/d04의 episode_kinds만 consult→install로 바뀌었다**. 행 수 18개·입력·새 프롬프트는 유지됐고 `score_rows`도 같다. 작성자는 K3 출력을 본 뒤 수정했음을 커밋과 채점기 모듈 머리말에 명시했다. 당시 60a26c2의 META에는 이 설명이 없었다. 설치 방법이라는 지침에 맞춰 라벨을 정리한 근거와, 그 결과 같은 출력의 점수가 16→18이 된 사실을 나눠 기록한다. 새 모델 실행·미열람 확인셋 통과·독립 성능 향상으로 보고하지 않는다.

후속 `95704b8`은 META와 생성 코드에 사후 변경·미측정 항목을 넣고 프롬프트 표기를 v0.007로 고쳤다. [메타 보완 대조](reviews/c-v07-v08-2026-11-18/metadata_followup.json)에서 eval·프롬프트·채점 함수 불변을 확인했다. 원 v0.7 폴더는 골드 보존 위치이며 원점수는 별도 GanpanAI@ddce6c42 측정 파일이므로, `kept`의 두 출처 표기만 분리할 필요가 있다. 이 보완으로 새로운 성능이나 의미 검증이 생긴 것은 아니다.

또한 kind 통과와 원천 의미 정합은 별개다. 예를 들어 v0.7 d02 첫 반복은 did.what에 접착 건조 안내를 쓰면서 실제 근거 index는 수리 도구를 가져오겠다는 턴5를 가리킨다. d03 세 반복과 d04 앞 두 반복의 did 원천5도 일반적인 응답인데 더 구체적인 작업 내용을 연결한다. 현재 채점기는 허용 S6와 인덱스·기대 kind를 보지만 **did.what/outcome이 해당 원천에서 도출되는지는 판정하지 않는다**. 이 원문 대조를 사람이 검수한 새 gold나 전체 의미 정확도로 확대하지 않았다.

## 좁은 코드 보완과 다음 확인

중단됐던 [C v0.6 fallback 재검증](reviews/m3-v02-r3-2026-11-17/c_v06_followup.md)을 다시 실행해 결과 바이트가 같음을 확인했다. 적격 pass 0개/여러 개에서 임의로 원천을 고르는 세 반례는 자료 오류로 바뀌었다. 유일한 pass가 부정 문장인 의미 반례는 별도 한계이며 실제 15행의 오류로 확대하지 않는다.

[실패 전파·C raw 소스 감사](reviews/m3-v02-r3-2026-11-17/execution_followup.md)도 마감했다. 명시적 settle+유효 키 경로는 보완됐지만 retry 네 곳은 wait 결과/tFailed를 읽지 않고, count fallback·종료 대기도 남는다. C raw 보존은 모델 content 문자열에 한정되며 실제 요청과 항목별 저장 영수증 전체를 대신하지 않는다.

우선 후속은 ① 재시도/키 없는 경로의 실패 전파, ② 합성 평가의 정확한 T 근거 구간과 C 요청·저장 결과 연결, ③ 새 C 지침으로 n08을 다시 측정할 때 고정한 입력·프롬프트·골드와 관측 단위를 함께 보존하는 것이다. 운영 배포·r5 실행은 이 감사에서 수행하지 않았다.
