## C episode 정책의 남은 불일치

리소너 `memory/S6_MEMORY_CONTRACT_v0.md:32,78`은 **promise와 episode 모두 실제 원천 턴 S6=pass**를 요구한다. 반면 C v0.005 지시문은 「약속을 뺐더라도(fix·block·unknown) … 그 일은 episode.did에 남긴다」고 한다. 실제 배포 소스의 `elda-orchestrator/src/prompts/eldacore/s6_memory_chat_end.md:35`도 같다.

약속을 거른 턴과 별개의 pass 턴에 실제 한 일이 있다면 그 일을 남길 수 있다. 그러나 지금 문구는 별도 pass 근거를 요구하지 않아, 유일한 원천이 block/unknown인 상담도 did로 남기는 해석을 허용한다. **M9를 유지한다면 did별 원천·pass 결합을 명시해야 한다.** 정책 변경을 승인된 것으로 간주하지 않는다.

`s6chatEnd.ts:191~208`은 did의 kind와 epoch를 확인해 저장하며 did별 S6 원천을 결합하지 않는다. C 채점기도 `s6_memory_chat_eval.py:105~123`에서 약속 원천 S6와 episode kind를 확인하므로 **C 13/13×3으로 episode 출처 관문을 검증한 것이 아니다.** 이는 이전 [S4/C 연결 감사](M4-SERVING-INTEGRATION-2026-11-16.md)의 did 출처 잔여와 같은 경계다.
