`83e0423e25`의 “이전 남색 대신…” 인용은 eval-v1 n14 q2 문장이 아니다. eval-v0 `build_dataset.py:347,350–352`의 다른 시나리오와 혼동됐다. 따라서 그 인용과 k08을 비교해 이번 n14 골드를 바꿔야 한다는 전제는 성립하지 않는다.

M3 봉인 기준은 **새 값 진술만으로 기존 값을 버리라는 의도를 확정하지 않고, 충돌은 확인 필요로 둔다.** “A 말고 B”, “이전 A 대신 B”처럼 자기 기존 값의 대체·철회가 명시되면 SUPERSEDE 양성으로 읽는 것이 두 자료와 맞는다. 기존 값을 반드시 문자 그대로 반복해야 한다는 규칙이나 특정 단어의 닫힌 목록을 새로 확정하는 것은 아니다.

리소너의 a/b 선택은 잘못 인용된 문장을 전제로 했으므로 먼저 원문·ID를 바로잡는다. **이번 frozen gold는 유지한다.** “새 기본값을 기억해 달라”까지 명시 정정으로 허용할 제품 정책을 택한다면 별도 정책 변경과 새 평가판으로 사전 고정한다. 원래 문장 자체에 해석 여지가 있으므로 signage 결과는 **봉인 CONTEST 기대와 SUPERSEDE 불일치**로 표현하며 런타임 의미 오판을 확정하지 않는다.

현재 T guard는 원천·문자열 근거를 검사한다. 오케가 말한 정확한 correction_evidence와 내림 0은 이번 export에 없으므로 독립 확인하지 못했다. 단어 목록은 인용·부정·제삼자 정정도 통과시키고 유효한 새로운 표현은 놓칠 수 있다. 보수적 정책을 원한다면 표지 유무만이 아니라 자기 귀속·기존 값 대체 의도·부정/인용을 함께 정의하고, 명확한 양성·모호한 충돌·어려운 음성을 별도 검증해야 한다.

실제 n14 guest는 CONTEST applied, needs_confirm=true이고 current=[]다. 어댑터가 profile.state=current만 current_values에 넣기 때문에 생긴 투영이다. 봉인 gold는 잠정 새 값도 current_values에 기대한다. 이 정의 차이를 알고도 gold나 제출 예측을 사후 수정하지 않았다.

## C 약속·episode와 새 평가 묶음

n08 양쪽 마지막 C는 ran=true/why=null, promises_seen=0이다. r2의 blocked 원천 보류와 다르며 호출 실패도 아니다. 중간 probe 답들이 앞의 약속을 “제안”으로 재분류한 뒤 마지막 pass fixture가 같은 미래 약속을 반복한다. probe의 답이 후속 C 입력에도 영향을 주는 혼합 이력이다. 정확한 C 요청·응답이 없어 이것을 누락의 단일 원인으로 확정할 수 없다.

n10 양쪽은 C 완료·episode 미저장만 확인된다. 모델 episode 미출력과 INSERT 실패를 구분할 자료가 없다. n03은 WITHDRAW applied와 값 제거가 확인되고 표시는 양쪽 `취향`이어서 canonical slot 대응이 별도 과제다.

기존 C v0.5에도 pass 미래 약속 양성 3개가 있었고 C v0.006에도 미래 약속·동일 문장 재등장의 pass 원천 선택 지시가 있었다. 다만 기존 13사례는 assistant 한 턴·총 2~3턴이라 mixed block/pass 동일 약속이나 중간 probe 이력을 포함하지 않았다.

새 `80b386f` C v0.6은 기존 13행을 바이트 그대로 보존하고 d01/d02 한국어·영어의 block turn1→pass turn5 동일 약속을 더한 15행이다. [새 평가 감사](reviews/m3-v02-r3-2026-11-17/c_v06_audit.md)에서 약속의 pass5 선택과 block1 대체 시 거부를 재현했다. episode did는 두 사례 모두 별도 turn3/none을 골라, 모든 원천이 pass5라고 할 수는 없다. `score_rows` 함수와 기존 13행의 합성 예측도 불변이다. 15/15은 정답 생성기·채점기의 자기검사이며 모델 점수가 아니다.

추가 순수 진단은 `_gold._src`가 적합한 pass를 찾지 못하면 첫 assistant로 돌아가는 경계를 확인했다. 그 턴이 관련 없는 pass여도 예측 텍스트에 기대 키워드를 넣어 자기검사가 통과할 수 있다. 키워드가 든 부정 문장을 앞선 pass로 두면 뒤의 실제 약속보다 먼저 고르고도 통과한다. 현재 추가 2행에는 이 반례가 없으며 기존 15행 오류로 확대하지 않는다. 적합한 근거 부재를 gold 생성 오류로 드러내는 보완과, 키워드 일치 이상의 의미 검토가 별도로 필요하다.

원출력 K=3 요청은 담당자의 후속 실행이다. 새 2행은 이미 관측한 n08 실패 유형에 대한 회귀 자료이며 독립 holdout 성능이나 전체 장기 대화 coverage를 뜻하지 않는다. META의 `prompt_pair`는 예전 v0.002 문자열이어서 실제 실행 C v0.006 해시는 별도 run 근거로 고정해야 한다.
