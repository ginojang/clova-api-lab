검토 원문은 Elda-Spec `df94ab80f048b25666d5bf856d0ab369f8603163`이다.
[harness/SPEC.md 절 N](https://github.com/ginojang/Elda-Spec/blob/df94ab80f048b25666d5bf856d0ab369f8603163/harness/SPEC.md#L277)과 [구현 조사](https://github.com/ginojang/Elda-Spec/blob/df94ab80f048b25666d5bf856d0ab369f8603163/harness/research/2026-11-16_long_term_memory_implementations.md)를 정적으로 읽었다.

## 결론과 범위

손님별 범위, 비동기 후보·통합, 정정·철회, 기억 제어를 나눈 방향은 유지한다.
남은 핵심은 주장 출처의 의미, 민감정보 탐지의 한계, 삭제와 늦은 작업의 경쟁, 인증된 식별, 회상 누락의 측정이다.
세계 시뮬레이션 NPC 기억은 원문 절 M·N의 범위 밖이다. 이 문서는 손님 대화 페르소나 계약만 다룬다.
계정 식별 방식·보관 복제·로그 기한 등 소유자 결정 대기 항목을 이 검토로 확정하지 않는다.

## 1. 원문 구간 존재는 자기 주장·진실·권한을 증명하지 않는다

- **원문:** H88(SPEC:287)은 사람 턴에서 손님이 자기에 대해 말한 내용만 후보로 삼는다. H97(:296)은 비사람 출처 주입의 쓰기 0을 평가한다.
- **빈틈:** 원문 span 대조는 글의 존재를 확인할 뿐, 인용·가정·부정·역할극과 자기 주장을 구분하지 못한다. 사용자 주장 자체도 외부 사실의 참을 보증하지 않는다.
- **제안:** 출처 검사는 입력 구간의 존재 확인으로 한정하고, 주장 주체·태도·승격 가능 여부는 별도 판단으로 기록한다. 승인된 결제·권한·실행 결과를 자기 주장만으로 만들지 않는다.
- **제안:** 저장된 내용은 필요한 경우 “손님이 그렇게 말했다”라는 지위를 보존한다. 기억의 자연어를 시스템 규칙이나 도구 실행 권한으로 승격하지 않는다.
- **평가 연결:** 같은 문장을 직접 자기 주장 / 타인 인용 / 가정 / 부정에 넣은 짝으로 쓰기 차이를 본다. 원문 구간은 모든 짝에 존재하게 한다.
- **외부 근거:** MINJA는 일반 사용자 질의로 기억을 오염시키는 연구다. `origin=human` 통과만으로 방어했다고 말할 수 없다. 공유 기억 또는 가능한 신원 위장이라는 적용 가정도 보존한다. [MINJA v5](https://arxiv.org/html/2503.03704v5)

## 2. 저장 금지 정책과 결정론 탐지기의 보장 범위를 나눈다

- **원문:** H89(:288)은 비밀번호·정확한 집 주소 등을 쓰기 전후 결정론 검사로 막는다고 한다.
- **빈틈:** 숫자 형식 검사는 일부 식별번호에 유용하지만 임의 문자열 비밀번호, 말로 풀어 쓴 값, 주소의 의미 범주를 모두 판별하지 못한다. 두 번 검사해도 같은 한계가 남는다.
- **제안:** 금지 정책은 유지하되 형식으로 강제할 수 있는 범위와 의미 판단이 필요한 범위를 구분한다. 불확실 후보의 처리 방식은 정책 소유자가 정한다.
- **제안:** “쓰기 후”가 영속 저장 이후인지 후보 검사 이후인지 명시한다. 금지 원문이 후보·원장·로그에 먼저 남았다면 최종 기억에 없다는 것만으로 무저장 준수를 주장하지 않는다.
- **평가 연결:** 합성된 정상 표기·분리 표기·일반 문장형 비밀과, 비슷하지만 비밀이 아닌 값의 짝을 둔다. 금지 항목의 저장 누락과 허용 사실의 과도 차단을 따로 센다.
- **해석 한계:** 알려진 탐침에서 `0/n`은 해당 탐침의 결과다. 모든 민감정보를 정규식으로 절대 차단한다는 증거가 아니다.

## 3. 삭제 이전 작업은 삭제 후 기억을 다시 만들 수 없어야 한다

- **원문:** H88(:287)은 비동기 추출·통합, H90(:289)은 진짜 삭제와 되살리지 않음, H94(:293)는 삭제 전파를 요구한다.
- **빈틈:** 삭제 전에 시작한 작업이 삭제 뒤 완료되어 `ADD`·`SUPERSEDE`를 커밋하는 순서는 아직 명시되지 않았다. 캐시 삭제·알림 전파와 별개인 경쟁이다.
- **제안:** “삭제 전 범위 상태를 읽은 작업은 삭제 후 커밋 불가”를 불변조건으로 둔다. 범위별 `memory_epoch`와 커밋 직전 검사, 취소 등은 구현 선택지다.
- **제안:** 기억 끄기 전에 시작한 작업에도 동일한 경계를 적용한다. 다시 허용된 뒤의 새 작업과 삭제 전 작업을 구분하여 정상적인 새 기억까지 막지 않는다.
- **평가 연결:** 같은 후보를 즉시 완료하는 경우와 삭제·끄기 뒤 늦게 완료하는 경우를 짝으로 둔다. 삭제 직후뿐 아니라 지연 작업·재시도 완료 뒤에도 확인한다.
- **증거:** 작업이 읽은 범위·세대, 삭제 순서, 최종 커밋 수락/거절, 후속 S4 주입을 연결한다. 삭제 영수증만으로 재삽입 방지를 판정하지 않는다.

## 4. principal 전달은 인증된 손님과의 결합을 대신하지 않는다

- **원문:** H86(:285)은 SQL 범위 조건, H95(:294)는 쿠키·환경변수·헤더·본문의 principal 전달과 `principal_link`를 정한다.
- **빈틈:** ID 형식과 범위 필터는 요청자가 다른 손님의 ID를 지정할 권한이 있는지를 결정하지 않는다. 기기 쿠키 하나가 같은 사람을 보장하지도 않는다.
- **제안:** 서버가 검증한 세션과 principal의 결합, 클라이언트 지정값의 덮어쓰기 거부, 로그아웃·공유기기 사용자 교체 시 효력 경계를 계약으로 둔다.
- **제안:** link/unlink 뒤 읽기·쓰기·삭제 범위와 합쳐진 기억의 귀속을 명시한다. 단순히 연결 행을 지운다는 뜻인지, 이미 합쳐진 내용을 분리한다는 뜻인지 구분한다.
- **평가 연결:** 동일 계정 재방문 / 다른 계정의 동일 기기 / 임의 principal 지정 / 연결 해제 뒤 재방문을 분리한다. 아직 결정되지 않은 동작은 통과·실패를 만들지 않고 정책 미정으로 둔다.
- **외부 근거:** Convai는 동일 `end_user_id`를 공유하면 기억도 공유한다고 명시하며, 장치 ID 대신 인증 체계의 계정 ID를 연결 전에 등록하도록 설명한다. [식별자 문서](https://github.com/Conv-AI/Convai-Documentation/blob/main/plugins-and-integrations/unity-plugin-beta-overview/features/long-term-memory/end-user-identity.md)

## 5. 검색·예산 때문에 빠진 기억을 회상 분모에 남긴다

- **원문:** H92(:291)는 상위 8~12개·800~1,200토큰 상시 블록과 topic/references 기반 검색을 정한다. H97(:296)은 기억 하류 점수와 안전 관문을 분리한다.
- **빈틈:** 유효한 사실이 저장됐어도 상시 블록에서 밀릴 수 있다. “지난번” 같은 표면 신호가 없는 자연스러운 요청은 검색 신호도 놓칠 수 있다.
- **제안:** prior-chat cue 보완과 별도로, 명시 회상 표현의 유무 및 목표 사실의 상시 블록 안/밖을 교차한 짝을 둔다. 예산을 넘긴 목표도 회상 분모에서 빼지 않는다.
- **제안:** 이후 600토큰안을 채택한다면 원문 초안의 예산과 별도 판으로 표시한다. 예산·항목 순위·검색 설정을 고정하지 않고 성능을 합산하지 않는다.
- **평가 연결:** 미저장·만료·충돌·검색 미발동·검색 누락·예산 제외·디코더 누락을 나눈다. 안전한 기권과 성공한 회상은 서로 다른 점수다.
- **증거:** 저장된 정답 항목, 검색 후보, 선택 항목, 실제 S4 주입 항목과 응답을 잇는다. 검색 성공 사례만 분모로 잡으면 회상 성능이 부풀려진다.

## M3의 짝 사례·원장·증거에 연결할 제안

아래는 M3가 채택할 수 있는 대응표이며, 확정 스키마나 새 실행 요청이 아니다.

| 짝 사례 | 원장·상태에서 볼 것 | S4와 하류에서 볼 것 |
|---|---|---|
| 자기 주장 / 같은 문장의 인용·가정 | 후보 출처·주장 주체·승격 연산·거절 이유 | 허용되지 않은 기억 항목이 실리지 않았는지 |
| 허용 정보 / 합성 비밀·우회 표기 | 후보·통합·원장에 남은 금지 값, 허용 사실 과도 차단 | 금지 값의 실제 주입 여부; 답에 안 나와도 주입은 별도 실패 |
| 정상 완료 / 삭제 뒤 지연 완료 | 읽은 세대·삭제 순서·최종 커밋 수락 여부 | 지연 작업 종료 후 철회·삭제 항목의 재주입 여부 |
| 손님 A / 동일 기기의 손님 B | 인증된 범위·link 판·읽기/쓰기 대상 | A 항목이 B의 실제 주입 본문·항목 목록에 들어갔는지 |
| 명시 회상 / 암시 회상, 예산 안 / 밖 | 정답 항목 존재·검색 발동·후보·순위·제외 이유 | 실제 주입 성공과 응답 회상 성공을 각각 계산 |

최소 연결 증거는 `case_id`, 짝 식별자, 범위, source turn/item ID, 처리 단계와 연산 결과, 판 정보, S4 주입 항목·본문 해시다.
세대·연산 순서·검색 제외 이유 등 추가 필드는 위 실패 원인을 구분하는 데 필요한 제안이며 기존 제공 필드라고 주장하지 않는다.
누수는 디코더가 말했을 때만 세지 않는다. **실제 모델 입력으로 확정된 S4 본문과 항목 목록**에서 다른 손님의 기억이 들어간 순간을 별도 판정한다.
다른 손님에게만 둔 합성 표식과 항목 출처를 함께 확인한다. 표식 불검출만으로 바꿔 말한 누수까지 없었다고 단정하지 않는다.
기억 읽기·쓰기를 모두 막아도 안전 관문만은 통과할 수 있으므로, 허용 사실의 저장·재방문 회상 성공을 짝으로 함께 보고한다.
케이스·짝·손님·대화·반복 수를 구분하고 정책 미정·증거 누락·평가 unknown을 성공으로 넣지 않는다. 최종 분모와 허용선은 M3 소유자가 고정한다.

## 외부 구현 조사에서 정정할 표현

- 조사 문서:17의 Inworld `flash + 장기 / 화제 때만 / 캐릭터마다 켬`은 현재 Runtime의 검증된 구현으로 사용하기 어렵다. 구 Character Studio는 종료됐다. [공식 종료 안내](https://docs.inworld.ai/character-studio-deprecation)
- 현재 Realtime 문서는 세션 facts·summary를 앱 DB에 저장하고 새 세션에 복구하도록 한다. 영속화·정정·삭제는 앱 책임이며, 자동 재만남 정확도 보장은 아니다. [현재 가이드](https://docs.inworld.ai/realtime/usage/long-term-memory)
- 연결된 Inworld 예제의 `retrieve(userId, _query)`는 최신 5개를 읽는다. 별도 벡터 검색 함수가 있다는 것만으로 기본 경로의 의미 검색까지 검증했다고 쓰지 않는다. [공개 코드](https://raw.githubusercontent.com/inworld-ai/language-learning-node/main/backend/src/services/memory-service.ts)
- 조사 문서:18의 Convai 삭제는 개별 기억 / 사용자×캐릭터 전체 / 사용자와 모든 캐릭터 기억을 구분해야 한다. 관리 API는 beta다. [기억 관리](https://github.com/Conv-AI/Convai-Documentation/blob/main/plugins-and-integrations/unity-plugin-beta-overview/features/long-term-memory/memory-management-api.md) · [사용자 관리](https://github.com/Conv-AI/Convai-Documentation/blob/main/plugins-and-integrations/unity-plugin-beta-overview/features/long-term-memory/end-user-management.md)
- 조사 문서:21의 “공통”은 각 제품 전체에 검증된 보장 대신 **우리의 설계 종합 제안**으로 읽어야 한다. 행별 제품 판·확인일·직접 URL·업체 설명/공개 코드 확인을 구분할 필요가 있다.

## 이미 팀이 논의 중인 항목 — 새 요구로 중복하지 않음

다음 목록은 부모 에이전트의 인계에 따른 논의 상태다. 구현 완료나 새 규격 반영을 독립 확인한 목록이 아니다.

- H88 턴후 후보와 즉시 정정의 충돌: chat 안 즉시 반영, principal 기억은 대화 종료 승격으로 분리하는 안.
- 충돌 보존과 `CONTEST`, episodes는 S6 pass 결과만 승격하는 안.
- `ltm_op` 원문까지의 삭제 범위, hearts insert-only 복제에서 삭제가 전파되지 않는 문제.
- VM RAM·CLI 프로세스의 잔존 내용, 삭제 알림 누락 뒤 catch-up 처리.
- `prior_chat` cue로 검색을 여는 안. 위 5번은 키워드 없는 회상과 예산 누락의 평가를 보충한다.

이 문서는 지정 연구 파일만 작성했다. 규격·소스·DB를 고치거나 실험을 수행하지 않았으며, 보류 중인 소유자 결정을 대신하지 않는다.
